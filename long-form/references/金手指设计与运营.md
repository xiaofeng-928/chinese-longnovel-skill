## 职责

用于主动设计、重构和阶段化规划金手指。现有金手指设计档案负责保存确认后的规则，本文件负责教 AI 怎样提出方案、制造选择、维持经济和形成长期玩法。

## 设计原则

### AI 先设计，用户校方向

- 根据题材、核心卖点、主角目标和用户偏好主动生成 `2-3套` 完整候选。
- 只询问会实质改变方向的问题；可由 AI 设计的属性、价格、任务和成长路线不得逐项推给用户填写。
- 推荐一套主方案并解释取舍。用户反馈“经营感不足”“系统感太强”等方向后，重构相关经济、成长和限制，不只局部增加功能。
- 用户确认前，候选方案不得写回正式配置、计划或状态仓库。

### 小说类型与金手指机制正交

小说类型标签决定读者期待什么；金手指机制画像决定主角如何操作和成长。保留“主类型 + 爽点模式 + 叙事侧重 + 当前阶段功能”，另行识别“主机制画像 + 次机制画像 + 资源机制 + 反馈机制”。不要按都市、末世、玄幻建立重复金手指模板。

### 核心设计内核

每套方案必须定义：

1. 核心幻想：读者持续期待的根本结果。
2. 核心动词：主角反复执行的购买、加点、建造、经营、培育、复制或推演等动作。
3. 输入资源与输出价值。
4. 选择结构：同一资源的竞争用途和机会成本。
5. 成长拓扑：平滑成长、子系统强化和战略跃升。
6. 限制代价：容量、冷却、损耗、维护、失败、暴露和机会成本。
7. 场景兑现：投资如何改变行动、效率、风险和外界反馈。
8. 长期演化：前中后期玩法动作怎样变化，而不只是数字增大。
9. 信息边界：金手指能感知什么，谁知道规则，外人如何解释结果。

## 机制画像

一本书可以组合多个画像，但必须指定一个主画像；次画像只辅助主玩法。

| 机制画像 | 必须设计的状态 |
|---|---|
| 商业经营 | 商品、货源、库存、定价、客户、支付能力、复购、利润、市场反馈 |
| 资产经营 | 性能、产能、维护、能源、空间、战损、设施、人员、折旧 |
| 基地/领地经营 | 人口、岗位、住房、治安、税费、公共服务、产能、秩序 |
| 属性加点 | 属性目录、等级上限、递增成本、前置、边际收益、场景验证 |
| 模块升级 | 模块槽位、前置、兼容、安装、维护、战损、玩法改变 |
| 空间种田 | 面积、地块、周期、产量、能耗、加工链、仓储、销售 |
| 签到抽奖 | 奖池、保底、冷却、重复奖励、领取条件、废奖处理 |
| 吞噬复制 | 槽位、来源、兼容、损耗、反噬、替换、组合规则 |
| 情报预知 | 范围、准确率、时效、盲区、验证成本、误判后果 |
| 传承技能 | 知识层级、熟练度、练习成本、外显边界、社会验证 |

## 成长与经济

### 成长拓扑

经营和养成类优先组合：

| 层级 | 频率 | 作用 |
|---|---|---|
| 平滑成长 | 高频 | 小幅解决具体短板，持续提供选择 |
| 子系统强化 | 中频 | 改变局部效率、操作方式或经营链 |
| 战略跃升 | 低频 | 解锁新玩法、地图、客户群、生产链或冲突级别 |

不强制所有小说使用三级，但必须说明缺少某一级的原因和替代爽点。升级至少改变操作、成本、风险、可处理需求、外界反应或下一轮选择之一；只加面板数字不算有效成长。

### 经济健康

存在累计资源时检查：

- 收入来源能否由剧情稳定触发，支出出口能否控制通胀。
- 价格增长是否匹配收入增长，旧商品和旧投资是否仍有用途。
- 是否存在维修、损耗、冷却、储备或机会成本。
- 是否长期只有唯一最优解，形成虚假选择。
- 高额奖励是否绑定重大风险、长期投入或阶段里程碑。
- 实物、货币、权限、图纸和额度是否分账。
- 奖励是否绕过现实物资、时间、运输和社会规则。

## 商店边界

### 系统商店

主角向系统购买加点、模块、权限、图纸或资源。维护：商品ID、分类、当前状态、价格、前置、等级上限、限购、刷新、购买效果和下一档成本。

### 主角经营商店

主角向顾客经营商品或服务。维护：货源、采购、库存、损耗、售价、顾客支付能力、订单、营业额、利润、复购、员工和市场反馈。

系统商店与主角经营商店必须分账。系统货币支出不能自动算作经营成本，顾客营业额也不能自动转成系统资源；转换必须有设计档案规则和正文证据。

阶段规划分别维护“系统商店快照”和“经营商店快照”。无对应商店时写“无”，不得虚构。

## 任务引擎

只要金手指主动派发任务，必须设计任务引擎；无任务机制写“无任务引擎”。任务不是临时奖励借口，而是连接世界变化、主角行动和成长资源的驱动器。

### 任务生成链

```text
系统感知来源 → 可验证触发条件 → 此刻派发的原因
→ 主角接受/拒绝/延后的规则 → 目标与完成判定
→ 奖励、失败、放弃和剧情后果
```

系统只能依据设计档案允许的传感器、绑定对象、规则判定或已接收信息派发任务。系统不知道的信息不能生成精准任务；任务包含未知情报时必须交代来源、可信度和信息成本。

### 任务类型

从新手引导、生存/维护、机会、里程碑、探索、对抗、经营、可选挑战中选择 `3-5种` 主类型。不要让任务系统无所不能。

单个任务至少定义：任务ID、类型、感知来源、触发条件、派发理由、接受规则、目标、完成判定、可用解法、合理时限、基础/额外奖励、失败/放弃后果、反作弊边界和剧情后果。

### 任务合理性闸门

1. 信息合理：系统能感知触发事实，不使用作者全知。
2. 时机合理：事件触发后派发，不事后追溯补发奖励。
3. 动机合理：任务符合系统稳定目标和价值边界。
4. 能力合理：派发时存在理论完成路径，不依赖临时外挂。
5. 时间合理：时限来自天气、距离、库存、敌情或交易窗口。
6. 奖励合理：奖励匹配难度、风险、投入和阶段经济。
7. 惩罚合理：可选任务优先使用失去机会和世界自然后果；强制惩罚必须预先定义。
8. 判定合理：成功条件派发时明确，结算时不改口径。
9. 主角能动性：主角能判断、准备、拒绝或选择解法。
10. 剧情合理：任务解决现实问题，结算后留下可见结果。

### 任务经济

- 先确定阶段奖励预算，再分配具体任务。
- 可重复任务使用递减收益、冷却、次数上限或状态门槛。
- 不把击杀、打脸或同一种行为设计成唯一收入来源。
- 任务奖励进入资源账，不自动购买唯一指定升级。
- 主角本来就要做的事可由系统确认价值；系统提供未知机会时必须服从感知边界；系统要求改计划时必须形成真实取舍。

## 阶段规划与章节闭环

金手指复杂或本阶段发生明显变化时，先生成 `plan/金手指发展_第X-Y章.md`，再生成同范围剧情细纲。阶段规划负责资源预算、两类商店快照、阶段任务池、成长路线和五章玩法循环；剧情细纲负责把它们落实为场景。

完整闭环：

```text
世界变化/经营需求 → 合理任务或机会 → 展示商店/属性/方案
→ 主角选择与机会成本 → 执行/使用 → 场景验证
→ 奖励、成本和经营结算 → 再投入 → 外界反馈/新短板/下一轮期待
```

不要求每章同时派任务、打开商店和升级。章节可分别承担触发、准备、选择、执行、结算、盘账、验证、复利或反馈；每个五章组至少形成一次可追溯闭环，连续两章不得只有系统提示。

## 状态分层

- 设计态：`novel-config.md`，保存确认后的永久规则和允许空间。
- 计划态：`plan/金手指发展_第X-Y章.md`，保存未来阶段安排。
- 运行态：主角状态仓库或独立金手指状态仓库，保存正文已发生事实。
- 章节增量：章节总结保存本章变化和证据。

默认内嵌 `总结/主角状态仓库.md`。同时满足任意两项时拆出 `总结/金手指状态仓库.md`：两种以上系统资源、商店状态、三条以上成长分支、属性/设施/模块树、持续冷却/债务/维护/战损。拆分后主角仓库只保留摘要和链接，禁止双重权威。

## 结构性问题

以下问题标为 `structural`，退回设计或阶段规划，不得由正文临时补功能：

- 核心动词单一、玩法重复、长期只有自动升级。
- 虚假选择、经济失衡、唯一收入来源或奖励通胀。
- 全知任务、救场任务、追溯奖励、判定漂移、木偶驱动。
- 商店临危出现正好解决问题的商品，或两类商店混账。
- 面板代替场景、升级无验证、反馈永远只有震惊。
- 后期扩展必须违反前期硬规则。
