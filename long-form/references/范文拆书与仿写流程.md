# 长篇范文拆书与原创仿写流程

本流程把扫榜样本沉淀为可复用范文资产，并把单篇或多篇范文的抽象机制迁移到原创长篇。范文库是跨项目共享资料，不属于任何一本小说项目。

## 一、目录模型

```text
D:\ai小说\小说\范文\
├── 番茄范文\
│   └── <大类题材>\
│       └── 《<作品名>》\
│           ├── 元数据.md
│           ├── 正文.txt
│           ├── 章节索引.md
│           └── 拆书报告.md
└── 起点范文\
    └── <大类题材>\
        └── 《<作品名>》\
            ├── 元数据.md
            ├── 正文.txt
            ├── 章节索引.md
            └── 拆书报告.md
```

- 标准根目录是 `D:\ai小说\小说\范文`；平台层统一命名为 `<平台>范文`，当前仅支持 `番茄范文` 和 `起点范文`。
- 平台下只按 `<大类题材>` 建目录，例如都市、玄幻、仙侠、科幻、历史军事、悬疑、游戏、言情。细分题材不建目录，写入 `元数据.md` 和 `拆书报告.md`。
- 同一作品跨榜单出现时只保留一个作品目录，在元数据中追加榜单证据，不重复建库。
- 平台无法确认或题材大类存在歧义时，先询问用户，不得猜测目录。

## 二、四种状态

### 1. 范文候选

扫榜样本默认只是候选。只保存平台、榜单、日期、榜位、书名、作者、链接、简介、标签、字数和可核验数据，不得把简介、目录、搜索摘要或模型记忆当作正文。

扫榜结束后列出“范文候选”。进入该清单的作品即建立元数据范文，但不等于已取得正文，也不得自动生成拆书报告；未进入候选清单的普通榜单样本只保留在 `选题决策.md`。

### 2. 元数据范文

范文候选建立目录并创建 `元数据.md`。若没有用户提供、明确授权或确认具有合法使用权的正文：

- `正文.txt` 不创建，或明确标为“待导入”；
- `元数据.md` 标记“不可拆书”；
- 只能做基于公开元数据的市场观察，不能生成声称基于全书的结构、人物、事件链或结局分析。

### 3. 局部正文范文

范文候选已经取得具有明确使用依据的连续开篇正文时，保存为 `正文.txt` 并标记“局部已导入”。默认获取第1-50章；若第一章完整收费正文在第50章前出现，则停在最后一章完整免费正文。

- 少于30章：标记“可用于开篇观察”，只分析黄金三章、前10章、开篇钩子和已兑现的核心循环。
- 30-49章：标记“可用于前期拆书”，分析已读范围的阶段结构、第一次高潮、爽点循环和章末钩子。
- 达到50章：标记“可用于前期拆书”，作为标准前期范文，可用于前50章抽象结构迁移。
- 示例：第39章开始收费时，只获取并保存第1-38章；不得尝试取得第39章正文，元数据写明“收费边界：第39章；实际范围：第1-38章”。
- 局部正文只分析实际读到的章节，不得推断未读章节的人物弧、伏笔回收、中后期结构或结局。

局部正文可以进入原创仿写，但只能迁移已读范围内有证据的抽象机制。迁移方案必须写明范文范围，不得声称参考了全书结构，仍须通过原创性闸门。

### 4. 全文深度范文

只有合法全文和来源依据均已落盘，完整读完正文后，才可生成 `拆书报告.md` 并标记为“可用于深度拆书”。正文后来更新时，拆书报告必须在同一任务内重做或校准；两者任一未完成，不得用于正式仿写。

`元数据.md` 使用固定字段和状态，不用近义词替代：

```markdown
# 《作品名》元数据
- 平台：
- 题材大类：
- 细分题材：
- 作者：
- 来源 URL：
- 正文来源类型：平台公开章节 / EPUB / TXT / Markdown / 直接粘贴
- 原始文件：无 / 文件名或原路径
- 榜单证据：榜单名 / 榜位 / 日期
- 授权/使用依据：
- 正文状态：待导入 / 局部已导入 / 全文已导入
- 正文版本：导入日期 + 章节范围 + 文件字节数
- 获取目标：第1-50章 / 收费前全部免费章 / 全文
- 实际章节范围：
- 收费边界：无 / 第N章开始收费 / 未检测
- 中止原因：达到50章 / 遇到收费 / 页面不完整 / 用户仅提供该范围 / 全文结束
- 拆书状态：不可拆书 / 可用于开篇观察 / 可用于前期拆书 / 可用于深度拆书
- 允许用途：市场观察 / 开篇机制迁移 / 前期结构迁移 / 全书结构迁移
- 拆书报告对应正文版本：
- 章节索引状态：待生成 / 已生成
```

正文版本或章节范围变化时，先把拆书状态退回“不可拆书”，更新报告及其对应版本后再恢复到与证据范围相符的状态。

## 三、章节获取规则

### 3.1 通用规则

1. 只使用用户提供的正文、用户确认具有使用依据的文件，或平台官方公开且无需绕过访问限制的完整免费章节。正文输入不按平台区分，可接受 EPUB、TXT、Markdown 文件或用户直接粘贴的正文；EPUB 必须是未加密 EPUB，不处理或绕过 DRM、密码与其他访问控制。
2. 目标默认是连续第1-50章，不跳章拼接。遇到首个VIP、订阅、付费、登录强制或正文不完整页面时立即停止。
3. 同时检查访问标记和正文完整性。标题、目录、搜索摘要、章节预览、只有开头数段的页面均不算完整正文。
4. 无论来源是网页、EPUB、TXT、Markdown 还是直接粘贴，均规范化为 UTF-8 的 `正文.txt`，并生成 `章节索引.md`。索引至少记录章节序号、标题、正文范围和来源；网页来源另记官方章节 URL 与访问日期，文件来源另记原文件名或原路径。
5. 不得绕过登录、风控、订阅或付费限制，不得使用第三方盗版站补齐缺章。
6. 原始 EPUB 或其他用户文件保留原文件，不覆盖、不删除；`正文.txt` 是拆书标准输入，`章节索引.md` 是定位与分块读取依据。无法可靠识别章节时停止拆书并报告异常，不按字数臆造章节。
7. 写入本地文件不等于载入模型上下文。长正文不得一次性载入全部正文；默认按第1-3章、第4-10章、第11-30章、第31-50章连续分块读取，每块更新事件索引和阶段摘要，再汇总拆书结论。实际不足50章时，最后一块止于实际末章。
8. 完整导入不等于全文分析。用户提供的文件包含50章以上内容时，保留原文件并完整规范化，除非用户明确要求另存局部副本，否则不得截断或删除第51章以后的原始内容；默认分析范围仍为连续第1-50章。只有用户明确要求全文深度拆书时，才继续按索引分块读完全文。

### 3.2 番茄小说正文待导入

1. 番茄范文候选在扫榜后建立元数据范文，写入榜单证据、官方链接和 `正文状态：待导入`。
2. 不得自动获取番茄正文，不创建伪正文或根据简介、目录、搜索摘要补写内容；在元数据中注明“等待用户手动补充正文”。
3. 用户手动补充正文后，按 3.1 的通用规则处理 EPUB、TXT、Markdown 或直接粘贴内容，生成 `正文.txt` 与 `章节索引.md`，再根据实际连续章节数更新状态并拆书。

### 3.3 起点中文网公开章节

起点桌面页可能返回风控探针；优先使用同一官方域名的移动端公开页面，不规避风控：

1. 从榜单或详情链接提取 `bookId`，打开 `https://m.qidian.com/book/<bookId>/`。
2. 在书籍页读取 `chapterContentInfo` 中的 `firstChapterId` 和 `nextChapterId`。若首项是“欢迎收藏”、公告或感言，跳过非正文节点，从下一正文章开始。
3. 正文章地址使用 `https://m.qidian.com/chapter/<bookId>/<chapterId>/`，读取当前章后按页面的 `next` 或 `nextUrl` 顺序前进。
4. 每章联合检查 `vipStatus`、`price`、`isBuy`、章节标题、标称字数和正文完整性。字段缺失或含义不明时，以“未登录状态能否返回完整正文”为最终边界，不根据单一字段猜测免费状态。
5. 当页面开始要求订阅、只返回预览、正文为空或字段显示付费时，将该章记为第一章完整收费正文并停止；上一章就是最后一章完整免费正文。
6. 默认最多保存第1-50章。若第39章开始收费，则保存第1-38章并在元数据记录边界；若前50章均完整免费，到第50章停止。

本节记录的是公开页面定位经验，不保证平台页面结构长期不变。结构变化时先重新验证，不得为完成数量目标而绕过限制。

## 四、范文入库

1. 确认平台、大类题材、作品名和是否已有同名目录。
2. 写入 `元数据.md`：来源状态、授权/使用依据、平台、题材大类与细分、榜单证据、链接、抓取/导入日期、正文状态、拆书状态。
3. 有合法局部正文或全文时，不按平台区分输入方式，统一生成 `正文.txt` 和 `章节索引.md`；按索引分块读取实际章节范围后，依照 `prompts/拆书与仿写提示词.md` 生成与范围匹配的 `拆书报告.md`。
4. 报告必须区分“原书事实”“基于事实的分析”“延伸建议”，不能把推测写成原书内容。
5. 元数据范文只复读 `元数据.md` 并确认 `正文状态：待导入`，不得创建空白 `拆书报告.md`；有正文并执行拆书后，再复读元数据、正文状态、章节索引和拆书报告，确认相互一致后才能报告拆书完成。

## 五、拆书

前期拆书和深度拆书都使用附件框架改造后的八步结构：题材与市场、核心卖点、世界观、人物、剧情与节奏、价值观、优缺点、迁移路径。局部正文将所有结论限制在实际章节范围；全文才能分析全书人物弧、完整伏笔回收、中后期扩张和结局。每条结论应尽量给出章节或正文证据；证据不足则标记“未证实”。

平台规则必须条件化：番茄范文可以分析黄金三章、首秀承诺、爽点密度和章末钩子；起点范文应基于其实际连载、推荐和付费阅读机制分析。没有真实平台数据时，不得把经验阈值写成已验证事实。

`拆书报告.md` 是范文库长期资产，只描述该范文本身及可抽象机制；不得填入新作人物、设定或剧情。

## 六、原创仿写

1. 列出同一大类题材下状态为“可用于前期拆书”或“可用于深度拆书”的范文，让用户选择一篇或多篇；不得自行选用没有正文使用依据的作品。
2. 目标项目已存在时直接使用。目标是全新长篇且项目尚不存在时，先按 `项目定位.md` 执行“范文驱动预初始化”：确认暂定书名、主类型和安全目录名，建立最小项目壳；不得先编造总大纲。
3. 将选定文件、参考维度和禁止复用项写入目标项目根目录 `参考素材.md`。
4. 读取范文正文、拆书报告、目标项目已有 `novel-config.md` 与 `plan/`；使用提示词生成 `plan/范文迁移方案.md`。局部正文范文必须同时读取其实际章节范围和禁止推断项。
5. 迁移方案只能保留抽象层机制，例如钩子原理、节奏密度、情绪波形、角色功能、冲突升级方式；不得复用原作专名、独特设定、具体人物关系、标志场景、事件顺序、台词或表达。
6. 完成原创性闸门：以下五项至少重新设计四项：人物与关系、核心冲突、事件因果链、反转机制、结局选择。五项高度相同，或任意三项存在可一一映射的连续对应时，结论为“应重构”，暂停大纲和正文生成。
7. 迁移方案确认后进入“大纲生成”；候选内容先在会话中生成，需要中断或跨会话复查时只写入 `plan/总大纲_待原创性复查.md`，不得提前占用正式总大纲文件名。
8. 二次原创性复查通过后才写入 `plan/总大纲.md`，补齐 `novel-config.md` 和主角状态仓库，并将项目状态从“待生成总大纲”改为“总大纲已确认”；复查失败时保留候选文件并标记“应重构”，不得写正式总大纲、黄金三章、细纲或正文。

## 七、多范文重组

- 每个关键机制注明来自哪篇范文、只参考什么抽象维度。
- 不得把 A 的人物关系、B 的事件链和 C 的结局直接拼接成换皮故事。
- 先合并为“机制候选池”，再围绕新作的一句话卖点、核心价值和目标读者重新选择。
- 冲突机制互斥、平台节奏不兼容或目标读者不同的部分必须舍弃，不强行融合。

## 八、归档边界

- 范文资产：`D:\ai小说\小说\范文\<平台>范文\<大类题材>\《作品名》\`。
- 项目选材记录：`<小说项目>\参考素材.md`。
- 项目原创迁移决策：`<小说项目>\plan\范文迁移方案.md`。
- 正式总大纲、细纲、黄金三章、正文和总结仍使用现有长篇工作流；范文报告与迁移方案不能替代正式大纲。
