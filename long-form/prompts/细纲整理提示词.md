# 细纲整理提示词

你要把用户提供的章节构想或现有笼统细纲，整理成可以直接指导正文创作的正式细纲。

## 输入原则

- 输入可能是流水账、口语、零散补充、对原细纲的修改意见，或手动插入章节构想。
- 输入已经表达的主线事件、人物目的、结局方向和用户明确要求必须保留。
- 细纲所在文件是正式规划文件；输出不使用“草稿”“候选细纲”或“待定细纲”状态。

## 允许的整理

- 补足事件之间的因果关系、场景目标、冲突升级、信息揭示、人物反应和章节收束。
- 将口语化表达改写为清晰、可执行的章节步骤。
- 拆分混在一起的动作顺序，明确事件发生条件和结果。
- 标注本章与主线、插入章节及前后章节的关系。
- 把金手指参与落到具体动作：任务触发、物资获取、点数/权限消耗、模块验证、结算反馈或限制代价；禁止只保留“系统提示”。
- 把实体物资与系统资源分账：实体物资写来源、数量/状态、消耗、余量和载重/容积限制；系统资源写生存点、权限、图纸碎片、模块状态及前后变化。两者不得默认互相兑换。

## 禁止的改写

- 不得擅自新增主要事件、角色、世界观规则、能力、资源或伏笔。
- 不得把支线扩写成主线，也不得因为表达不完整而替用户决定未确认的剧情。
- 发现事实冲突、时间冲突或因果缺口时，先列出冲突和需要确认的点，不直接覆盖既有事实。

## 输出格式

输出一个可直接写回原章节归档的完整章节块，至少包含：

```markdown
### 第X章：章节标题

#### 本章定位
#### 核心事件
#### 事件展开
#### 人物变化
#### 信息与伏笔
#### 章节收束
#### 写作边界
```

每章还必须补充以下两个账目字段，直接放入上述章节块中：

```markdown
#### 物资账变动
- 实体物资：获取/消耗/损失/余量变化；无变化写“无变化（原因）”。
- 系统资源：生存点、权限、图纸碎片、模块状态的前值→后值；不得写无法由前章推导的余额。
- 资源限制：载重、容积、燃油、保质期、战损或权限限制如何影响本章行动。

#### 金手指交互
- 本章环节：触发/获取、使用/消耗、结算/再投入、限制/代价、外界反馈中实际发生的环节。
- 场景化结果：系统动作如何改变具体行动、资源或敌我判断；不能只写面板文字。
- 与下一章闭环：本章收益或代价在下一章如何被使用、验证或继续承担。
```

整理窗口按每5章自检：至少3章必须有具体金手指交互，至少1章完成“获取→使用→结果/限制”闭环；连续两章不得只有系统名词或空泛的“获得奖励”。若原构想没有足够交互，只能从既有金手指设计档案中补足资源消化、结算、限制和外界验证，不得新增系统能力。

整理完成后，正式细纲可直接被正文生成、审查和上下文组装流程读取。
