# 金手指阶段规划提示词

用于在生成同范围剧情细纲前，规划未来最多50章的金手指发展。执行前完整读取 `references/金手指设计与运营.md`。

## 输入

- 当前规划范围：第X-Y章，`Y-X+1 <= 50`
- `novel-config.md` 金手指设计档案与类型标签：
- 总大纲中本阶段目标和金手指演化边界：
- 当前主角状态仓库：
- 当前金手指状态仓库（如有）：
- 前一阶段金手指发展文件与阶段总结（如有）：
- 最近已写正文和章节总结中的实际偏离：
- 本阶段剧情硬节点、时间锚和禁止提前解锁项：

## 前置校准

1. 区分设计态、计划态和运行态。正文事实优先；计划不能冒充已获得状态。
2. 当前规则不足以支持本阶段时停止，列出需返回“金手指设计/重构”的 `structural` 问题。
3. 无金手指时不创建空文件。金手指简单且本阶段无明显变化时，可输出“沿用设计档案，无独立阶段文件”及理由。
4. 有任务引擎时先核对感知边界、任务类型、完成判定、奖惩与反作弊规则。

## 规划要求

- 使用区间维护资源预算，不把未来精确数值当成事实。
- 分开维护系统商店快照和经营商店快照；无对应商店写“无”。
- 有任务引擎时建立阶段任务池，先控制阶段奖励预算，再分配任务。
- 每个五章组安排需求/任务、候选方案、选择、执行、结算、再投入和外界反馈中的合理组合。
- 不要求每章派任务、看商店或升级；允许积累、维护、放弃、失败、验证、复利和盘账章。
- 所有新增商品、任务类型、权限和成长分支必须来自设计档案；需要越界时退回设计流程。
