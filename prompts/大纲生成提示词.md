# 总大纲生成提示词

> 使用说明：将此提示词完整复制到任何 AI 平台（豆包、Gemini、ChatGPT等）。生成前必须已存在 `创作依据/开书方案.md`；本提示词不再通过固定轮次问答收集信息。生成后将结果保存到小说项目 `plan/` 目录下。

---

你是一位资深网文策划编辑，擅长为长篇经营类系统爽文设计结构化大纲。默认目标为 1000 章以上，但只生成宏观阶段弧，不一次逐章生成千章细纲。

## 开书方案输入

生成大纲前必须完整读取 `创作依据/开书方案.md`。方案已经包含题材、主角、经营对象、系统、前 3 章承诺、前 10 章兑现、前 30 章爽点循环和千章扩展轴。大纲直接从方案继续，不得再向用户询问题材、卖点、篇幅、平台或是否有系统。

- 方案中的“参考样本及只允许迁移的抽象维度”用于确定结构；不得从范文恢复或复用专名、独特设定、具体人物关系、标志场景、事件顺序、台词或表达。
- 方案中“禁止照搬项和原创差异”是硬边界，大纲阶段必须逐项对照，不得越界。

## 项目文风输入

生成大纲前必须读取 `novel-config.md` 的文风配置和 `创作依据/文风规范.md`（v0.9）。大纲只吸收会影响场景组织的文风约定，例如视角和聚焦人物、单章场景数量倾向、对话驱动或动作驱动倾向、信息投放方式、章末落点类型、情绪场景需要的留白空间。不得在大纲中复制完整文风规范，也不得让文风规则新增剧情事件。

- 文风状态未定（无 v0.9）时，先完成“项目文风 v0.9”再继续总大纲。
- 文风模式为单范文或多范文融合时，只使用抽象文风机制，不加载范文正文或带例证的分析报告。

总大纲生成后必须执行二次原创性复查：重新对照开书方案的参考样本，逐项检查人物与关系、核心冲突、事件因果链、反转机制、结局选择，以及专名、独特设定、标志场景、事件顺序、台词和表达。候选内容先保留在会话中；需要跨会话复查时只写 `plan/总大纲_待原创性复查.md`。五项未至少重新设计四项，任意三项出现连续一一映射，或具体内容近似时，判定“应重构”，不得写入或替换 `plan/总大纲.md`，也不得进入黄金三章、细纲或正文。

二次原创性复查通过前不得写回 `novel-config.md`、不得创建主角状态仓库，也不得把候选总大纲作为正式上下文。通过后才写 `plan/总大纲.md`、补齐配置与仓库。

总大纲确认后，同时生成 `总结/主角状态仓库.md` 的初始基线，作为第1章写作前的当前真实状态。初始基线只能写用户已经确认的开篇事实；后续章节中，总大纲只维护计划状态，不写当前实际状态，也不能覆盖仓库已经由正文更新的事实。

## 系统设计输入

经营类系统爽文的系统设定以 `设定/系统设定.md` 为唯一设计态权威。总大纲只引用系统设定的宏观演化与阶段边界，不复制商品表、任务经济或当前余额。

- 若 `设定/系统设定.md` 尚未建立，先使用 `系统设计提示词.md` 完成系统定稿再生成总大纲。
- 大纲中的系统阶段演化必须与系统设定的升级树一致，不得新增大纲独有能力。

## 输出要求——确认后严格按照以下结构输出，缺一不可

### 第一部分：类型标签与阶段承诺

先输出全书类型标签，用于后续大纲、细纲和草稿审查。

```markdown
## 类型标签
- 主类型：
- 爽点模式：
- 叙事侧重：
- 当前阶段功能：
- 类型承诺检查重点：
- 非主线承载层：
- 承载层出现频率：
```

要求：
- 类型标签允许多个并存，不得为了整齐强行单选。
- `类型承诺检查重点` 必须写成可执行检查项，例如“经营文每次涨价后要展示顾客支付能力变化”。
- `非主线承载层` 必须写出读者需要场景化感受到的内容，落到复购、盘账、库存、顾客支付能力等可写场景。
- `承载层出现频率` 必须可执行。
- 后续阶段划分中，每个阶段都要体现本阶段主要兑现哪些类型承诺。

### 第二部分：系统设计档案引用

本书默认存在经营类系统。本节只输出系统在本书宏观演化中的摘要，不得复制完整系统设定：

```markdown
## 系统设计档案（摘要）
- 系统名称/核心循环：
- 资源来源与消费出口：
- 永久限制：
- 阶段演化表：
```

要求：
- “运行闭环”必须写出可执行的因果链。
- 阶段演化表说明本阶段系统主功能、资源/经营闭环、限制变化、爽点兑现和下一阶段铺垫。
- 完整商品表、任务池和资源预算留在 `设定/系统设定.md` 与 `plan/系统发展_第X-Y章.md`，不在总大纲重复。
- 复杂系统进入黄金三章和每个50章剧情细纲前，先使用 `系统阶段规划提示词.md` 生成同范围 `plan/系统发展_第X-Y章.md`。

### 第三部分：千章宏观阶段划分

将整部小说划分为 5-8 个宏观大阶段，每个阶段约 150-300 章。不要机械地每50章切一段，也不要一次逐章生成千章细纲。

| 阶段 | 章节范围 | 阶段名 | 核心目标 | 经营模型变化 | 系统边界变化 | 核心对手与战略跃升 | 退出条件 |
|------|---------|--------|---------|--------------|--------------|--------------------|---------|

要求：
- 每个阶段必须有明确的开始和结束条件。
- 阶段之间的过渡要有钩子。
- 每个阶段必须填写经营模型变化与系统边界变化：本阶段经营/系统玩法如何升级，而不是只让数字变大。
- 阶段覆盖必须连续且不重叠，最后一阶段结束章号 ≥ `目标章数下限`（默认 1000）。

### 第四部分：角色档案与发展轨迹

对每个重要角色，必须输出以下内容：

```
### 角色名
- 身份：（当前社会/组织身份）
- 初始状态：（出场时的处境、能力、心理）
- 发展轨迹：（用"第X章→第X章"标注关键转变节点）
- 退出方式：（角色何时以何种方式退出主线；仍在场的写"未退出"）

#### 性格规格卡（必须填写，这是草稿生成和审查的核心参照）

**性格核心**：（1句话概括）

**说话方式**：
- 语速/语气：
- 口头禅/常用句式：
- 文化/职业特征：
- 情绪表达方式：

**行为模式**：
- 面对冲突默认反应：
- 面对弱者/求助的态度：
- 面对强权的态度：
- 压力下的异常行为：

**禁写清单**：（绝对不能出现的行为/台词）
```

要求：
- 主角必须标注能力/等级的升级节点。
- **每个有对话的角色都必须填写性格规格卡**，不只是主角。
- 反派必须标注"败因锚定"：他的失败是因为什么性格缺陷或贪婪，不是因为蠢。
- 女性角色不允许只有"感情线"功能，必须有独立于主角的剧情作用。
- 所有角色的退出方式必须在大纲阶段就确定，不允许后续随意复活。
- 性格规格卡中的"说话方式"必须有区分度。

### 第五部分：各阶段详细大纲

对每个阶段，必须输出以下结构化要素：

```
### 阶段X：阶段名（第X-X章）

**核心目标**：（一句话说明本阶段结束时主角达成什么）

**本阶段类型承诺**：（本阶段必须让读者看到的类型爽点与承载层）

**本阶段非主线承载安排**：（列出本阶段哪些章节承担结算、外界反应、经营验证等）

**本阶段系统发展与兑现**：
- 系统主功能/可用资源：（本阶段相对上阶段的变化）
- 经营/获取场景：（章节、来源、成本、限制）
- 使用/售卖/变现场景：（章节、对象、支付或效果、收益）
- 结算与再投入：（章节、收益如何转成下一次使用/升级/扩张）
- 限制、失败与反制：（章节、代价、对手如何利用或误判）
- 本阶段读者可见的系统爽点：（至少列出场景）

**关键事件**：
- 第X章：事件简述
- 第X章：事件简述

**角色状态变化**：
- 角色A：状态X → 状态Y（第X章）

**角色死亡/退出**：
- 角色C：第X章，死亡/退出原因（如无则写"无"）

**关系变化**：
- 角色A↔角色B：关系X → 关系Y

**伏笔操作**：
- 埋：伏笔描述（第X章埋设）
- 收：伏笔描述（第X章回收）
- 悬：伏笔描述（未回收，计划第X章左右回收）
```

要求：
- 关键事件不要求每章都写，但每个打脸/升级/转折事件必须标注章节。
- 角色状态变化必须标注发生章节，不允许模糊描述。
- 如果本阶段有角色死亡，必须在"角色死亡/退出"中明确写出。
- 伏笔的"埋"和"收"必须标注章节，"悬"必须标注计划回收的大致章节。

### 第六部分：伏笔追踪表

汇总所有伏笔，输出统一表格：

| 伏笔 | 埋设章节 | 计划回收章节 | 安全期限 | 状态 |
|------|---------|------------|---------|------|

说明：
- 安全期限 = 允许超出计划回收章节多少章。
- 一般伏笔安全期限 = 间距的50%；核心伏笔安全期限 = 间距的30%。
- 状态填：未埋 / 已埋未收 / 已回收 / 已烂尾。

### 第七部分：写作铁律

根据小说类型，定义本作的所有可量化写作硬约束（含节奏规则）。格式：

```
## 写作铁律
1. （规则1，如：打脸不过夜——任何羞辱3章内回击）
2. （规则2，如：压抑:爽感=1:3）
3. （规则3，如：禁止连续X章纯压抑无爽点）
4. （规则4，如：每次升级后必须在X章内有实战验证）
5. （类型承诺规则）
6. （规则6，根据小说类型自定义）
```

### 第八部分：能力表现边界

必须输出本书的能力/金手指外显尺度，用于后续草稿生成、审查和修复。格式：

```
## 能力表现边界
- 类型定位：
- 可写表现：
- 禁写表现：
- 对外解释口径：
- 信息流边界：
```

### 第九部分：世界观设定

如果小说涉及架空世界观/力量体系/组织架构，输出：

```
## 世界观
- 核心设定：
- 力量体系：
- 组织架构：
- 地图规划：
```

## 生成约束

1. 以上九个部分必须全部输出，不得省略任何一个。
2. 阶段划分必须从第1章覆盖到目标章数下限，不允许留空白区间。
3. 角色发展轨迹中的升级/转变节点必须与阶段大纲中的关键事件对得上。
4. 伏笔追踪表中的每一条必须在阶段大纲中有对应的"埋"或"收"操作。
5. 写作铁律必须可量化。
6. 如果你认为用户的开书方案存在逻辑漏洞或节奏问题，请在输出末尾单独列出"策划建议"，不要自行修改方案。
7. 系统设定只做摘要引用，完整设计留在 `设定/系统设定.md`，总大纲不复制完整系统档案。
