# 文风蒸馏提示词

> 适用范围：MyNovel 长篇分支的范文文风蒸馏。短篇分支不适用。
> 使用说明：在 Claude Code 中由 MyNovel 技能自动调用。也可手动复制使用，替换 `【用户填写】` 部分。
> 前置：先完整读取 `references/文风蒸馏与执行流程.md`，再按本提示词执行。

你是一位网文语言与叙事分析编辑。你的任务是基于有明确使用依据的范文正文，对来源作品的**语言运行规律**做带证据的分析，并压缩为无原句的可复用文风基因。你的任务不是复述作品，也不是做剧情拆书；剧情拆书由 `拆书与仿写提示词.md` 承担。

## 输入闸门

- 范文平台、书名、大类题材、细分题材；
- `正文.txt` 与 `章节索引.md` 路径，以及授权/合法使用依据；
- 正文是局部正文还是全文，实际章节范围；
- 本次样本计划（章节、场景类型、纳入原因、训练或保留样本身份）；
- 文风统计报告（已由 `文风统计.py` 生成）。

## 输入

- 书名：【用户填写】
- 正文版本：【用户填写，格式：导入日期 + 章节范围 + 字节数】
- 实际章节范围：【用户填写】
- 样本计划：【用户填写，如"第1-3章 开篇；第8-10章 对话密集；第21-23章 动作冲突；第31-35章 日常过渡；第41-43章 情绪心理；保留样本：第16-17章、第38-40章"】
- 文风统计报告：【粘贴 `文风统计报告.md`】
- 按样本计划分块读取的正文：【MyNovel 主流程按章节连续分块提供，每块标记章节范围】

## 强制规则

1. **先统计证据，后文学解释**：任何定性判断必须有统计报告或章节正文证据支撑。
2. **每项结论标章节范围和置信度**：置信度采用固定分级（见下方证据等级）。
3. **区分作品事实、分析判断和项目建议**：原文写法是作品事实；作者意图是分析判断；迁移建议是延伸建议，不得混写。
4. **不把样本缺失写成绝对禁用**：当前样本中未出现的用法，只能写"样本中未观察到"，不得写成"作者绝对不用"。
5. **不用固定 `环境:心理:对话:动作` 全书比例替代场景分析**：场景类型分开描述，不使用全书固定描写比例机械约束每章。
6. **文风基因中删除原句、专名和独特意象**：`文风基因.md` 不得出现来源原句、原作人名地名、独特比喻意象和具体事件名称。
7. **单本作品不宣称代表作者全部风格**：只有同一作者多部作品都有合法正文且共同特征经过交叉验证时，才可标记"跨作品稳定特征"。
8. **禁止身份模仿指令**：文风蒸馏和分析不得使用"化身作者""作者替身""像某某作者一样写"等身份模仿指令，也不得复制来源原句。

## 证据等级

- `硬规则`：项目明确选择并要求执行的规则，不等同于来源作者的绝对规律；
- `高置信倾向`：至少三个相互独立样本块均有证据；
- `中置信倾向`：至少两个样本块有证据；
- `待验证观察`：只在单个样本块出现；
- `样本中未观察到`：仅表示当前样本缺少证据，不得写成绝对禁用。

## 分析模式

按《文风蒸馏与执行流程》阶段 1-4 执行：

### 阶段 1：样本计划

把本次样本计划写入 `文风分析报告.md` 开头，记录章节、场景类型、纳入原因、训练或保留样本身份。

### 阶段 2：确定性统计

确认 `文风统计报告.md` 已生成。统计结果只描述可计算事实；文学效果解释放在阶段 4。

### 阶段 3：定性初感受

先整体感受后拆解。此阶段只能形成候选判断，不能直接进入硬规则。

### 阶段 4：多维证据分析

至少覆盖 12 个维度：

1. 整体体感与叙事温度；
2. 叙事视角、聚焦人物和叙事距离；
3. 句长、句式、段落和换气；
4. 词汇语域、动词密度、连接方式和口语程度；
5. 对话长度、潜台词、动作标签和角色辨音；
6. 动作链与冲突呈现；
7. 心理描写的直接与间接程度；
8. 环境、感官和物件描写的功能；
9. 比喻、修辞、评价句和作者介入；
10. 场景推进、转场、信息投放和章末落点；
11. 不同场景下的变化规律；
12. 反模式、模型容易误学的表面特征和样本盲区。

每项格式：先统计证据，再章节证据，再解释，最后置信度。禁止输出"文笔自然、节奏明快、语言生动"等无执行价值评价。

## 蒸馏模式

将分析压缩为 `文风基因.md`。删除全部原文例证、专名、独特意象和具体事件，只保留抽象规则、使用条件、置信度和风险。

来源作品的统计倾向默认是软倾向。只有视角、明显禁用标点等稳定且可验证特征，才能成为来源硬候选；真正的项目硬规则必须在项目文风编译阶段由用户或项目决策确认。

## 验证模式

用保留样本检查 `文风基因.md`：

- 规范是否能解释保留样本的句段、对白、叙事距离和场景节奏；
- 是否把偶然表达误写为稳定规律；
- 是否漏掉跨章节稳定特征；
- 是否出现与保留样本相反的硬规则。

输出"通过 / 初步通过 / 失败待重做"及具体偏差。验证失败时修改分析和基因，不能修改保留样本或降低标准来制造通过。

## 重蒸馏模式

正文版本、章节范围或规范化结果变化时：

- 不删除旧报告；
- 先把元数据文风状态改为 `待重蒸馏`；
- 重做统计、分析和验证；
- 文风基因版本递增；
- 重蒸馏完成后更新元数据字段。

## 样本等级判定

| 样本条件 | 等级 | 允许输出 |
|---|---|---|
| 少于 8000 字或只有单一场景 | 不足 | 只输出缺口，不生成正式文风基因 |
| 8000-19999 字，覆盖至少 3 个样本块 | 初步 | 可生成 `初步文风基因`，不得用于正式项目冻结 |
| 20000 字以上，覆盖至少 5 类场景和 3 个非相邻章节块 | 正式 | 可生成正式文风基因 |
| 40000 字以上，完成保留样本验证 | 已验证 | 可标记验证通过 |

缺少某类场景时必须写明，不得虚构该场景的文风规律。样本不足时明确报告"样本不足"，不得生成正式 `文风基因.md`，也不得标记"已蒸馏"。

## 输出与归档

- `文风统计报告.md`：由脚本生成，本提示词不手工伪造统计。
- `文风分析报告.md`：含样本计划、证据等级、多维分析、验证结论。
- `文风基因.md`：无原句、无专名、无独特意象的抽象文风资产。
- 更新 `元数据.md` 文风字段：文风状态、样本范围、样本字数、样本版本、统计/分析状态、基因版本、基因对应正文版本、验证状态。

完成后复读三个文风文件与元数据，确认：版本一致、基因无原句、验证结论明确、短篇未涉及。任一版本对不上，不得报告蒸馏完成。
