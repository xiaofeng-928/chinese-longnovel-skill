# 分阶段大纲细化提示词

> 使用说明：总大纲生成后，用它来细化指定章节窗口，替换 `【用户填写】` 部分。本提示词只用于**大纲/细纲生成**，不用于直接生成章节正文；只要任务已明确是生成大纲/细纲，就不适用“正文创作五章直写闸门”，可一次生成一个50章归档段（如第201-250章），但必须按每5章为一组组织输出与自检。细化后保存到 `plan/` 目录对应50章归档文件。

---

你是一位资深网文策划编辑。现在需要你将总大纲中的指定章节窗口细化，为每一章提供足够的写作指引。

**细化窗口边界**：
- 先解析 `start`、`end`，计算 `count = end - start + 1`。
- 先区分任务类型：如果用户要的是**生成分阶段大纲/细纲**，`count <= 50` 时可以一次生成一个50章归档段；这属于规划层任务，不适用正文创作的五章直写闸门。
- 如果用户实际要求的是**直接生成章节正文**，不要使用本提示词；应切换到正文草稿生成流程，并按正文创作闸门处理。
- 批量生成50章细纲时，必须按每5章一个小组组织输出与自检，避免长输出后半段重复、漂移或忘记前文约束。
- 50章是归档单位。第101-105章和第106-110章都应保存/追加到 `大纲_第101-150章.md`；第201-250章应保存到 `大纲_第201-250章.md`。

## 输入

- 书名：【用户填写】
- 当前阶段：【用户填写，如"阶段2：初露锋芒"】
- 当前细化范围：【用户填写，如"第101-105章"；外部大模型批量生成时可写"第201-250章"】
- novel-config核心信息：【粘贴写作铁律+角色档案/性格规格卡+伏笔追踪表+世界观设定】
- 总大纲核心信息：【粘贴总大纲的阶段划分表+本阶段前后相邻阶段的核心目标+全书主线/反派线/升级线】
- 本阶段在总大纲中的描述：【粘贴总大纲中该阶段的6项结构化要素】
- 黄金三章微操细纲：【粘贴 `plan/黄金三章_微操细纲.md`；用于回扣开篇承诺、核心卖点、主角初始爽感和读者预期。如果文件不存在，写"无"】
- 全部阶段总结：【粘贴 阶段总结/ 下所有阶段总结，包含已完成阶段和当前进行中阶段；如果这是第一阶段且暂无总结，写"这是第一阶段"。AI需要知道前面所有阶段的关键事件、角色状态、死亡/退出名单、能力资源状态和未回收伏笔】
- 历史细纲（防重复用）：【粘贴当前细化范围之前100章的细纲；例如生成第201-250章时，粘贴第101-200章细纲。如果前文不足100章，则粘贴全部已有细纲。此项用于识别冲突手段、爽点形态、章末钩子、反派压迫套路是否短期重复】
- 最近5章正文全文：【粘贴当前细化范围起始章 S 之前5章正文，即第max(1, S-5)章到第S-1章；前文不足5章则粘贴全部已有正文；如果尚无正文，写"无"】
- 最近10章章节总结：【粘贴当前细化范围起始章 S 之前10章章节总结，即第max(1, S-10)章到第S-1章，必须包含最近5章正文对应总结；如果尚无总结，写"无"。此项用于检查细纲与已写正文的章末状态、角色认知、信息流边界和因果债是否衔接】
- 近期本阶段冲突手段台账：【可由用户预先粘贴；如果没有，AI必须先根据"历史细纲+全部阶段总结+最近10章章节总结+最近5章正文"自行提炼后再生成细纲。台账格式见下方"生成前置步骤"】

## 生成前置步骤——先建冲突手段台账，再写细纲

在输出逐章大纲之前，你必须先完成以下分析，不得跳过：

1. 从输入材料中提炼"近期本阶段冲突手段台账"。重点扫描：历史细纲、全部阶段总结、最近10章章节总结、最近5章正文、总大纲中本阶段关键事件。
2. 台账至少覆盖当前细化范围之前100章；如果前文不足100章，则覆盖全部已有细纲。对最近20章内的同一反派/同一主冲突线要标记为高敏重复风险。
3. 台账格式：

```markdown
## 近期本阶段冲突手段台账

| 章节/范围 | 反派/势力 | 目标对象 | 场景/战场 | 手段类型 | 具体手段 | 结果/失败原因 | 后续是否可复用 |
|---------|---------|---------|----------|---------|---------|--------------|--------------|
| 第X章 | XX势力 | 主角/盟友/产业 | 医馆/大会/舆论场/供应链 | 物理打压/行政打压/经济封锁/舆论污名/法律程序/内部策反/技术压制 | 具体做法 | 如何被化解或留下什么后果 | 禁止原样复用/可升级变体/可远期回环 |
```

4. 基于台账列出本次细化范围的"可用新手段方向"。优先选择与近期不同的战场或压迫链条，例如：供应链、资金链、证据链、舆论场、行政程序、行业规则、病患安全、内部策反、竞赛规则、地图转移、信息差误导。
5. 如果总大纲要求某章使用的手段与近期台账高度相似，不要直接照抄。必须改造成升级变体，或在该章的"冲突手段差异点"中说明它为什么不是重复。
6. 同步提炼"衔接硬约束"：上一章/上一阶段章末状态、主角能力与资源、反派状态、角色死亡/退出名单、未回收伏笔、角色认知边界、后文禁止误写。后续细纲不得违反这些硬约束。

## 输出要求——按以下结构逐章输出

---

### 每章大纲格式

```
<!-- chapter:X outline:start -->
#### 第X章：章节名

**场景**：（本章主要场景）

**开篇设计**：
- 开篇方式：（从“行动中开场 / 反常情境 / 震撼对话 / 倒计时压力 / 重大发现 / 危机时刻 / 谜团浮现 / 背叛开场 / 重大选择 / 结局预告”中选择一种；如不适用，写“承接式开场”）
- 承接上一章：（说明如何接住上一章结尾钩子/状态；如为第1章，写“无，负责建立开篇承诺”）
- 前20%牵引：（异常、压力、冲突、信息差或行动目标）

**核心事件**：（1-3句话概述本章发生了什么）

**登场角色**：（列出本章出场角色）

**爽点/钩子**：
- 爽点：（如有，如"当众施针患者站起""周子轩败北"）
- 章末钩子类型：（从“突然揭示 / 紧急危机 / 未完成动作 / 身份或立场反转 / 两难选择 / 神秘线索 / 时间限制 / 承诺或威胁 / 言外之意 / 回声或呼应 / 留白钩子 / 升级预告 / 冲突预告”中选择一种）
- 章末钩子：（结尾留什么具体期待驱动下一章）

**角色状态变化**：（如"叶辰：经验值+200"，如无则写"无"）

**伏笔操作**：（如"埋：XXX""收：XXX"，如无则写"无"）

**冲突手段差异点**：（对照"近期本阶段冲突手段台账"，说明本章冲突/打压/阻碍的新意在哪里；如果本章无外部冲突，写"无外部冲突"）

**与下一章衔接**：（本章结尾如何自然过渡到下一章开头）
<!-- chapter:X outline:end -->
```

保存到50章归档文件时，每章必须保留 `outline:start/end` 锚点。重生成某章时只替换对应锚点之间内容，不得重复追加或覆盖其他章节。

### 细化约束

1. **每章必须有章末钩子**——没有钩子的章节读者会弃书。章末钩子必须从本提示词给出的扩展类型中选择，不能只写“留下悬念”。短期内不要反复使用同一种钩子形态；如果必须回环，必须升级为更强变体。

2. **相邻章节的事件必须有因果或时间顺序**——不允许出现"上一章在A城，下一章突然在B城且未交代转移"

3. **爽点密度**：每3章至少1个明确爽点（打脸/升级/逆转/实力展示）。连续2章无爽点时，第3章必须安排爽点

4. **压抑不超过2章**：如果某章是纯压抑（主角被质疑/打压/陷入困境），下一章或下下一章必须有翻盘。连续3章纯压抑是红线

5. **角色行为不得违背性格锚定**：总大纲中每个角色都有"性格锚定"关键词，本章中该角色的行为必须符合锚定。如果需要角色做出反常行为，必须在本章中给出合理的心理转变过程

6. **必须与已完成阶段的状态衔接**：本阶段第1章的角色状态、场景、情绪必须与上一阶段最后1章连续。已死亡的角色不得在本阶段出场。已回收的伏笔不得再以"新发现"形式重新埋设

7. **如果本阶段有系统/力量体系升级**：升级前必须有至少1章的积累/困境铺垫，升级后必须在2章内有实战验证。升级不能"白嫖"

8. **每章字数指引**：根据事件密度给出建议——纯铺垫章1800-2500字，打脸/升级高潮章2500-3500字，过渡章1500-2000字

9. **短期冲突手段去重**：最近20章内，禁止让同一反派/势力对同一目标在同一场景使用同一手段原样重复。例如"派人砸医馆"已经发生过，短期内不能再写成"派更多人砸同一个医馆"。如果必须回环，必须升级为不同压迫链条或不同战场，例如从物理打砸升级为供应链封锁、账户冻结、证据污染、媒体围剿、行政程序、行业资格战、内部策反等。当前细化范围之前100章内出现过的高频手段，也要尽量避免密集复用，除非地图、反派、目标或解决方式已经明显变化。

10. **远期重复宽松**：当剧情跨度超过50章、地图/位面/主要反派发生明显变化，或作者有意做结构性回环时，可以复用相似套路，但必须换目标、换战场、换代价或换解决方式。不要为了去重而牺牲类型爽感，也不要把短期重复包装成"升级"。

---

```markdown

- 主角等级/能力：
- 主角资源/人脉：
- 在场角色及状态：
- 已埋未收伏笔：
- 下阶段需要的铺垫：
```

这份快照将被用作下一阶段细化的"上一阶段末尾状态"输入。

同时输出一份**生成后细纲轻量自检**。自检只检查细纲级硬伤，不做正文级文风、AI味、反应词密度审查：

```markdown
## 生成后细纲轻量自检

| 检查项 | 结论 | 证据/依据 | 如需调整的方案 |
|------|------|----------|-------------|

| 死亡/退出角色是否被误写回场 | 通过/风险/需调整 | 对照全部阶段总结 | 如无问题写"无" |
| 与最近5章正文和最近10章总结是否衔接 | 通过/风险/需调整 | 对照章末状态、角色认知、信息流边界 | 如无问题写"无" |
| 与总大纲/本阶段核心目标是否衔接 | 通过/风险/需调整 | 对照总大纲阶段目标和关键事件 | 如无问题写"无" |

| 主角能力/资源/人脉是否越级或回退 | 通过/风险/需调整 | 对照阶段总结和章节总结 | 如无问题写"无" |
| 信息流是否越界 | 通过/风险/需调整 | 谁知道什么、谁不该知道什么 | 如无问题写"无" |
| 节奏是否满足爽点密度和压抑上限 | 通过/风险/需调整 | 对照写作铁律和本轮章节安排 | 如无问题写"无" |

## 本次调整记录
- 若自检中存在"需调整"，先列出原方案问题，再给出替换后的最终大纲。
- 若只有"风险"，说明风险理由和保留原因。
- 若全部通过，写"自检通过，无需调整"。
```

若任一检查项结论为"需调整"，必须先修正对应章节，再输出最终版章节大纲；不得把明知有硬伤的版本作为最终稿。
