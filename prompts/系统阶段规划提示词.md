# 系统阶段规划提示词

用于在总大纲扩窗和同范围剧情细纲前，先校准永久系统设计并规划未来最多50章的金手指发展。执行前完整读取 `references/系统设计与运营.md` 和 `references/规划窗口与防抢跑.md`。

## 输入

- 当前规划范围：第X-Y章，`Y-X+1 <= 50`
- 所属宏观阶段：stage ID、阶段范围、核心目标、关键事件、退出条件和剩余窗口数
- `设定/系统设定.md` 完整系统设计档案，以及 `novel-config.md` 的系统版本和类型标签：
- 总大纲中本阶段目标和金手指演化边界：
- 当前主角状态仓库：
- 当前系统状态仓库（如有）：
- 前一阶段系统发展文件与阶段总结（如有）：
- 最近已写正文和章节总结中的实际偏离：
- 本阶段剧情硬节点、时间锚和禁止提前解锁项：
- 后续窗口与下一宏观阶段必须保留的系统成长、任务、商品、权限和验证场景：

## 前置校准

1. 区分设计态、计划态和运行态。正文事实优先；计划不能冒充已获得状态。
2. 先审核永久系统设计是否足以支持当前窗口。需要新增规则、商品、权限、任务类型或成长分支时，先更新 `设定/系统设定.md`、递增系统设定版本并列出变更；未完成设计更新不得继续。
3. 当前规则不足以支持本阶段时停止，列出需返回“系统设计/重构”的 `structural` 问题。
4. 每个准备生成细纲的窗口都必须创建同范围系统发展文件。系统简单、本窗口无变化或 legacy 项目无金手指时，生成最小计划并把不适用栏目写明“无/沿用设计档案”，但仍须保留实体物资预算、主角/系统进度上限和四类防抢跑边界；不得省略文件。
5. 有任务引擎时先核对感知边界、任务类型、完成判定、奖惩与反作弊规则。

## 规划要求

- 使用区间维护资源预算，不把未来精确数值当成事实。
- 分开维护系统商店快照和经营商店快照；无对应商店写“无”。
- 有任务引擎时建立阶段任务池，先控制阶段奖励预算，再分配任务。
- 每个五章组安排需求/任务、候选方案、选择、执行、结算、再投入和外界反馈中的合理组合。
- 不要求每章派任务、看商店或升级；允许积累、维护、放弃、失败、验证、复利和盘账章。
- 所有新增商品、任务类型、权限和成长分支必须来自设计档案；需要越界时退回设计流程。
- 把宏观阶段成长任务按剩余窗口数分配，禁止当前窗口完成阶段退出条件、后续窗口专属跃升或下一阶段系统内容。
- 明确输出“本窗口可完成、只推进不完成、禁止提前解锁/结算、后续窗口保留”，供下一步总大纲窗口合同锁定。

输出并保存为 `plan/系统发展_第X-Y章.md`：

```markdown

- 本窗口可完成：

- 禁止提前解锁/结算：
- 后续窗口保留：
- 下一宏观阶段禁止项：

## 阶段规划自检

```

任一自检发现无法通过的结构问题时，不输出伪装成最终版的计划；标记 `structural` 并退回系统设计/重构。当前任务属于细纲前置链时，系统计划通过后必须继续执行 `prompts/规划窗口准备提示词.md`，不得直接跳到细纲；用户明确只要求独立系统计划时可在此停止，但必须报告下一道窗口准备闸门尚未完成。
