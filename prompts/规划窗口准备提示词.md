# 规划窗口准备提示词

用于在同范围系统发展计划完成后、剧情细纲生成前，扩展宏观总大纲、锁定剧情预算并更新 `novel-config.md`。执行前完整读取 `references/规划窗口与防抢跑.md`。

## 输入

- 目标规划窗口：第S-E章，`E-S+1 <= 50`
- `novel-config.md` 当前/下一计划窗口和权威路径：
- `plan/总大纲.md` 全文：
- 同范围 `plan/系统发展_第S-E章.md`：
- `设定/系统设定.md` 当前版本与本次设计更新结果：
- 当前 committed 主角/系统状态快照：
- 已有窗口合同和历史细纲：
- 用户明确保留、延后或禁止提前出现的内容：

## 执行步骤

1. 确认同范围系统发展计划已经完成，且不存在未解决的 `structural` 问题；否则停止。
2. 定位目标窗口所属 `MYNOVEL:STAGE`，核对阶段起止章、核心目标、关键事件、退出条件和下一阶段入口。
3. 若阶段缺少可执行退出条件，先补充 `exit_condition`；退出条件必须只能在该阶段最后一个窗口完成。
4. 首次扩展该宏观阶段时，一次创建覆盖整个阶段的全部连续 `MYNOVEL:WINDOW` 块。不得只创建目标窗口。
5. 给每个窗口分配独立功能、必须完成项、只推进项、主角进度上限、系统进度上限、禁止提前完成项、后续保留量和窗口末未解决项。后续窗口必须有足够的专属事件、角色变化、经营闭环和系统发展负载。
6. 当前目标窗口结合系统发展计划生成覆盖该窗口全部章号的完整“五章剧情预算”；每行四个预算单元都写具体事件或边界，不使用省略号、表头复述、`TODO/TBD/待定` 等占位文本。未来窗口统一写 `system_plan: null`，五章预算可先标记 `pending`，但窗口级剧情负载不得为空。
7. 非最后窗口强制 `stage_exit_allowed: false`；最后窗口才设为 `true`。所有窗口都禁止借用下一宏观阶段专属事件。
8. 更新 `novel-config.md`：写入协议版本、目标窗口范围、同范围系统计划路径、窗口合同 ID 和剧情预算锁。正文正在使用当前窗口时，把待生成范围写入“下一”字段，不覆盖当前指针；剧情细纲路径在文件生成验证前保持 `null`。
9. 运行窗口准备自检。任一项失败时只输出阻断报告，不得进入细纲生成。

## 剧情容量分配原则

- 不把宏观阶段核心目标当成当前窗口的待办清单全部完成；必须按剩余窗口数分配。
- 每个窗口既要有阶段性结算，也必须留下明确的后续压力、资源债、关系变化或未完成行动。
- 关键里程碑按总纲计划章号所在窗口执行，不得前移；章号只有在用户确认重构总纲时才能调整。
- 当前窗口五章预算必须继续分配到每个五章组，避免前10章完成整个50章任务后只剩重复冲突。
- 若现有宏观阶段内容不足以支撑全部窗口，先扩充总纲的中间演化、经营反馈、角色链和压力孵化；不得借用下一阶段内容填充。

## 输出与写回

### 一、总大纲更新

- 只补充目标宏观阶段的 `exit_condition` 和“规划窗口合同”部分。
- 已有窗口块按 `window_id` 精确替换，不重复追加，不覆盖其他阶段。
- 窗口块严格使用 `references/规划窗口与防抢跑.md` 的 schema。

### 二、novel-config 更新

只更新对应稳定字段，不复制剧情描述：

```markdown
- 规划窗口协议版本：1
- 当前窗口合同：window-XXXX-YYYY / null
- 当前剧情预算锁：locked / null
- 下一窗口合同：window-XXXX-YYYY / null
- 下一剧情预算锁：locked / null
```

同时核对既有 `当前/下一计划窗口` 与 `当前/下一系统计划` 指向目标范围；`当前/下一剧情细纲` 只有在细纲文件生成并验证后才登记路径。首个细纲生成前保持 `project_status: 总纲`；正文中提前准备下一窗口时保持 `project_status: 正文中`。

### 三、窗口准备自检

```markdown
## 窗口准备自检
| 检查项 | 结论 | 证据/修订 |
|---|---|---|
| 同范围系统发展计划是否先完成 | 通过/阻断 | 文件与设计版本 |
| 宏观阶段是否完整拆成全部连续窗口 | 通过/阻断 | 窗口列表 |
| 阶段退出条件是否只允许最后窗口完成 | 通过/阻断 | exit_condition 与 stage_exit_allowed |
| 当前窗口是否保留足量剧情给后续窗口 | 通过/阻断 | reserved_for_later |
| 是否禁止提前解锁、提前回收和进入下一阶段 | 通过/阻断 | forbidden_early_completion / next_stage_forbidden |
| 主角与系统的窗口末计划上限是否明确 | 通过/阻断 | protagonist_progress_cap / system_progress_cap |
| 当前窗口五章剧情预算是否完整锁定 | 通过/阻断 | 五章预算表 |
| config 窗口合同、范围和预算锁是否一致 | 通过/阻断 | manifest 字段 |
| 剩余剧情是否足以支撑剩余章数 | 通过/阻断 | 各窗口独立负载 |
```

全部通过后才能转入 `prompts/分阶段大纲细化提示词.md`。
