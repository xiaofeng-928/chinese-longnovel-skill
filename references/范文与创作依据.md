# 范文与创作依据

本文是 vNext 的唯一范文与创作依据流程文档，合并了旧《范文拆书与仿写流程》与《文风蒸馏与执行流程》。范文结构分析（拆书）与文风分析是两条独立工作流：拆书负责"写了什么、为什么有效"，文风蒸馏负责"语言如何运行"。

## 目录

- 一、概念与权威关系
- 二、范文目录与状态
- 三、范文入库与正文边界
- 四、拆书、文风统计与蒸馏
- 五、项目文风编译与校准
- 六、原创迁移、审查与归档

## 一、概念与权威关系

| 名称 | 归属 | 作用 | 是否含原文例证 |
|---|---|---|---|
| 拆书报告 | 范文 | 题材、人物、剧情、爽点、结构和市场机制 | 可含少量定位证据，不大段引用 |
| 文风统计报告 | 范文 | 确定性统计结果 | 不含大段原文 |
| 文风分析报告 | 范文 | 对语言和叙事规律进行带证据解释 | 可含必要短例证和章节定位 |
| 文风基因 | 范文 | 将稳定规律压缩为可复用抽象参数 | 禁止出现原句、专名和独特意象 |
| 项目文风规范 | 小说项目 | 当前项目唯一可执行的文风权威源 | 禁止出现来源原句 |
| 文风校准记录 | 小说项目 | 记录版本变更、偏移和人工反馈 | 只引用项目自身正文位置 |

### 冲突优先级

正文生成、审查和修复出现冲突时，严格按以下顺序处理：

```text
用户本次明确要求
> 已发生正文事实、状态仓库与信息边界
> 本章正式细纲和后续两章边界
> 角色性格规格卡与角色说话方式
> 项目文风规范中的硬规则
> 项目文风规范中的软倾向
```

文风不能成为修改事实、提前消耗后续事件、增加角色或改变金手指规则的理由。

### 唯一权威源

- 范文文风的证据权威：`正文.txt` + `章节索引.md` + `文风统计报告.md`。
- 范文抽象文风资产：`文风基因.md`。
- 单本小说当前执行文风：`创作依据/文风规范.md`。
- `novel-config.md` 只保存文风入口、状态、版本、生效章节和少量核心约定，不复制完整规范。
- `参考素材.md` 只记录选择了哪些范文、参考哪些维度和禁止复用项，不复制完整文风基因。

## 二、范文目录与状态

本流程把扫榜样本沉淀为可复用范文资产，并把单篇或多篇范文的抽象机制迁移到原创长篇。范文库是跨项目共享资料，不属于任何一本小说项目。

### 2.1 目录模型

```text
<长篇范文库>/
├── 番茄范文\
│   └── <大类题材>\
│       └── 《<作品名>》\
│           ├── 元数据.md
│           ├── 原始文件\                # 可选；用户原始 EPUB/TXT/Markdown 等
│           ├── 正文.txt
│           ├── 章节索引.md
│           ├── 拆书报告.md
│           ├── 文风统计报告.md           # 执行文风蒸馏后生成
│           ├── 文风分析报告.md           # 执行文风蒸馏后生成
│           └── 文风基因.md               # 执行文风蒸馏后生成
└── 起点范文\
    └── <大类题材>\
        └── 《<作品名>》\
            ├── 元数据.md
            ├── 原始文件\                # 可选
            ├── 正文.txt
            ├── 章节索引.md
            ├── 拆书报告.md
            ├── 文风统计报告.md           # 执行文风蒸馏后生成
            ├── 文风分析报告.md           # 执行文风蒸馏后生成
            └── 文风基因.md               # 执行文风蒸馏后生成
```

- 标准根目录是 Skill 启动时解析出的 `<长篇范文库>`；平台层统一命名为 `<平台>范文`，当前仅支持 `番茄范文` 和 `起点范文`。
- 平台下只按 `<大类题材>` 建目录，例如都市、玄幻、仙侠、科幻、历史军事、悬疑、游戏、言情。细分题材不建目录，写入 `元数据.md` 和 `拆书报告.md`。
- 同一作品跨榜单出现时只保留一个作品目录，在元数据中追加榜单证据，不重复建库。
- 平台无法确认或题材大类存在歧义时，先询问用户，不得猜测目录。

### 2.2 四种状态

### 1. 范文候选

扫榜样本默认只是候选。只保存平台、榜单、日期、榜位、书名、作者、链接、简介、标签、字数和可核验数据，不得把简介、目录、搜索摘要或模型记忆当作正文。

扫榜结束后列出“范文候选”。进入该清单的作品即建立元数据范文，但不等于已取得正文，也不得自动生成拆书报告；未进入候选清单的普通榜单样本只保留在 `选题决策.md`。

### 2. 元数据范文

范文候选建立目录并创建 `元数据.md`。若没有用户提供、明确授权或确认具有合法使用权的正文：

- `正文.txt` 不创建，或明确标为“待导入”；
- `元数据.md` 标记“不可拆书”；
- 只能做基于公开元数据的市场观察，不能生成声称基于全书的结构、人物、事件链或结局分析。

### 3. 局部正文范文

范文候选已经取得具有明确使用依据的连续开篇正文时，保存为 `正文.txt` 并标记“局部已导入”。起点官方公开章节默认连续获取到第一章完整收费正文之前，不设 50 章下载上限；其他局部正文来源未约定范围时，默认规范化连续第1-50章。任何来源遇到收费、访问控制或正文不完整时，都停在最后一章完整免费正文。

- 少于30章：标记“可用于开篇观察”，只分析黄金三章、前10章、开篇钩子和已兑现的核心循环。
- 30-49章：标记“可用于前期拆书”，分析已读范围的阶段结构、第一次高潮、爽点循环和章末钩子。
- 达到50章：标记“可用于前期拆书”，作为标准前期范文，可用于前50章抽象结构迁移。
- 示例：第39章开始收费时，只获取并保存第1-38章；不得尝试取得第39章正文，元数据写明“收费边界：第39章；实际范围：第1-38章”。
- 局部正文只分析实际读到的章节，不得推断未读章节的人物弧、伏笔回收、中后期结构或结局。

局部正文可以进入原创仿写，但只能迁移已读范围内有证据的抽象机制。迁移方案必须写明范文范围，不得声称参考了全书结构，仍须通过原创性闸门。

### 4. 全文深度范文

只有合法全文和来源依据均已落盘，完整读完正文后，才可生成 `拆书报告.md` 并标记为“可用于深度拆书”。正文后来更新时，拆书报告必须在同一任务内重做或校准；两者任一未完成，不得用于正式仿写。

`元数据.md` 使用固定字段和状态，不用近义词替代：

```markdown
# 《作品名》元数据
- 平台：
- 题材大类：
- 细分题材：
- 作者：
- 来源 URL：
- 正文来源类型：平台公开章节 / EPUB / TXT / Markdown / 直接粘贴
- 原始文件：无 / 文件名或原路径
- 榜单证据：榜单名 / 榜位 / 日期
- 授权/使用依据：
- 正文状态：待导入 / 局部已导入 / 全文已导入
- 正文版本：导入日期 + 章节范围 + 文件字节数
- 获取目标：收费前全部免费章 / 连续第1-50章 / 用户指定范围 / 全文
- 实际章节范围：
- 收费边界：无 / 第N章开始收费 / 未检测
- 中止原因：遇到收费 / 页面不完整 / 用户仅提供该范围 / 全文结束
- 拆书状态：不可拆书 / 可用于开篇观察 / 可用于前期拆书 / 可用于深度拆书
- 允许用途：市场观察 / 开篇机制迁移 / 前期结构迁移 / 全书结构迁移
- 拆书报告对应正文版本：
- 章节索引状态：待生成 / 已生成
- 文风状态：不可蒸馏 / 可初步蒸馏 / 可正式蒸馏 / 已蒸馏 / 待重蒸馏
- 文风样本范围：
- 文风样本字数：
- 文风样本版本：
- 文风统计状态：待生成 / 已生成
- 文风分析状态：待生成 / 已生成
- 文风基因版本：无 / vX.Y
- 文风基因对应正文版本：
- 文风验证状态：未验证 / 初步通过 / 已通过 / 失败待重做
```

正文版本或章节范围变化时，先把拆书状态退回“不可拆书”，更新报告及其对应版本后再恢复到与证据范围相符的状态。

### 2.3 拆书与文风蒸馏分离

拆书和文风蒸馏是两条独立工作流，互不替代：

- `拆书报告.md` 负责"写了什么、为什么有效"：题材、卖点、人物、剧情结构、爽点、节奏和原创迁移。拆书可以在没有文风蒸馏时独立完成。
- `文风统计报告.md`、`文风分析报告.md`、`文风基因.md` 负责"语言如何运行"：句法、叙事距离、对白习惯、场景呼吸和标点习惯。文风蒸馏也可以在不生成项目迁移方案时独立完成。
- 拆书默认不自动执行文风蒸馏；用户明确要求“拆书并蒸馏文风”时，先按本流程拆书，再按 `范文与创作依据.md` 执行文风蒸馏。
- 用户明确要求"文风蒸馏""提炼范文的文风""生成文风基因"时，直接进入 `范文与创作依据.md`，不要求先拆书。

`元数据.md` 的文风字段与正文版本联动：正文版本、章节范围或规范化结果变化时，先把文风状态退回 `待重蒸馏`，不得继续声称旧文风基因对应新正文版本。已有项目不会自动切换到新范文版本，必须显式重新编译项目文风。

### 2.4 章节获取规则

#### 通用规则

1. 只使用用户提供的正文、用户确认具有使用依据的文件，或平台官方公开且无需绕过访问限制的完整免费章节。正文输入不按平台区分，可接受 EPUB、TXT、Markdown 文件或用户直接粘贴的正文；EPUB 必须是未加密 EPUB，不处理或绕过 DRM、密码与其他访问控制。
2. 获取范围按来源决定：起点官方公开章节默认连续获取到收费边界前，不设 50 章下载上限；其他局部正文来源未约定范围时默认连续第1-50章。不得跳章拼接；遇到首个VIP、订阅、付费、登录强制或正文不完整页面时立即停止。
3. 同时检查访问标记和正文完整性。标题、目录、搜索摘要、章节预览、只有开头数段的页面均不算完整正文。
4. 无论来源是网页、EPUB、TXT、Markdown 还是直接粘贴，均规范化为 UTF-8 的 `正文.txt`，并生成 `章节索引.md`。索引至少记录章节序号、标题、正文范围和来源；网页来源另记官方章节 URL 与访问日期，文件来源另记原文件名或原路径。
5. 不得绕过登录、风控、订阅或付费限制，不得使用第三方盗版站补齐缺章。
6. 原始 EPUB 或其他用户文件保留原文件，不覆盖、不删除；`正文.txt` 是拆书标准输入，`章节索引.md` 是定位与分块读取依据。无法可靠识别章节时停止拆书并报告异常，不按字数臆造章节。
7. 写入本地文件不等于载入模型上下文。长正文不得一次性载入全部正文；默认按第1-3章、第4-10章、第11-30章、第31-50章连续分块读取，每块更新事件索引和阶段摘要，再汇总拆书结论。实际不足50章时，最后一块止于实际末章；明确扩大分析范围时，第51章以后继续按章节连续分块。
8. 完整入库不等于全文分析。正文包含50章以上内容时必须完整保留合法取得的目标范围，不得因默认分析范围而截断或删除第51章以后的内容；默认分析范围仍为连续第1-50章。正文版本扩展但报告仍只分析前50章时，校准报告的正文版本，并同时写明“已入库范围”和“实际分析范围”，不得声称新增章节已经分析。只有用户明确要求扩大范围或全文深度拆书时，才继续按索引分块读取后续正文。

#### 番茄小说正文待导入

1. 番茄范文候选在扫榜后建立元数据范文，写入榜单证据、官方链接和 `正文状态：待导入`。
2. 不得自动获取番茄正文，不创建伪正文或根据简介、目录、搜索摘要补写内容；在元数据中注明“等待用户手动补充正文”。
3. 用户手动补充正文后，按 3.1 的通用规则处理 EPUB、TXT、Markdown 或直接粘贴内容，生成 `正文.txt` 与 `章节索引.md`，再根据实际连续章节数更新状态并拆书。

#### 起点中文网公开章节

起点桌面页可能返回风控探针；优先使用同一官方域名的移动端公开页面，不规避风控：

1. 从榜单或详情链接提取 `bookId`，打开 `https://m.qidian.com/book/<bookId>/`。
2. 在书籍页读取 `chapterContentInfo` 中的 `firstChapterId` 和 `nextChapterId`。若首项是“欢迎收藏”、公告或感言，跳过非正文节点，从下一正文章开始。
3. 正文章地址使用 `https://m.qidian.com/chapter/<bookId>/<chapterId>/`，读取当前章后按页面的 `next` 或 `nextUrl` 顺序前进。
4. 每章联合检查 `vipStatus`、`price`、`isBuy`、章节标题、标称字数和正文完整性。字段缺失或含义不明时，以“未登录状态能否返回完整正文”为最终边界，不根据单一字段猜测免费状态。
5. 当页面开始要求订阅、只返回预览、正文为空或字段显示付费时，将该章记为第一章完整收费正文并停止；上一章完整的正文节点就是最后一章完整免费正文。
6. 从第一正文章开始沿 `next` / `nextUrl` 连续前进，直到首个收费边界或全书目录结束，不设 50 章下载上限。若第39章开始收费，则保存第1-38章；若第89章开始收费，则保存到第88章，并在元数据记录实际范围和收费边界。
7. 免费链中的上架感言、请假条、公告、成绩汇报等明确非正文节点只用于继续定位下一节点，不写入 `正文.txt` 或 `章节索引.md`。是否为非正文必须根据标题、正文功能和篇幅联合判断，不能只因篇幅短就删除小说正文。

本节记录的是公开页面定位经验，不保证平台页面结构长期不变。结构变化时先重新验证，不得为完成数量目标而绕过限制。

### 2.5 范文入库

1. 确认平台、大类题材、作品名和是否已有同名目录。
2. 写入 `元数据.md`：来源状态、授权/使用依据、平台、题材大类与细分、榜单证据、链接、抓取/导入日期、正文状态、拆书状态。
3. 有合法局部正文或全文时，不按平台区分输入方式，统一生成 `正文.txt` 和 `章节索引.md`；按索引分块读取实际章节范围后，依照 `prompts/范文结构与文风分析提示词.md` 生成与范围匹配的 `拆书报告.md`。
4. 报告必须区分“原书事实”“基于事实的分析”“延伸建议”，不能把推测写成原书内容。
5. 元数据范文只复读 `元数据.md` 并确认 `正文状态：待导入`，不得创建空白 `拆书报告.md`；有正文并执行拆书后，再复读元数据、正文状态、章节索引和拆书报告，确认相互一致后才能报告拆书完成。

### 2.6 拆书

前期拆书和深度拆书都使用附件框架改造后的八步结构：题材与市场、核心卖点、世界观、人物、剧情与节奏、价值观、优缺点、迁移路径。局部正文将所有结论限制在实际章节范围；全文才能分析全书人物弧、完整伏笔回收、中后期扩张和结局。每条结论应尽量给出章节或正文证据；证据不足则标记“未证实”。

平台规则必须条件化：番茄范文可以分析黄金三章、首秀承诺、爽点密度和章末钩子；起点范文应基于其实际连载、推荐和付费阅读机制分析。没有真实平台数据时，不得把经验阈值写成已验证事实。

`拆书报告.md` 是范文库长期资产，只描述该范文本身及可抽象机制；不得填入新作人物、设定或剧情。拆书报告内不顺带生成文风基因；用户需要文风资产时，另行进入 `范文与创作依据.md`。

### 2.7 原创仿写

1. 列出同一大类题材下状态为“可用于前期拆书”或“可用于深度拆书”的范文，让用户选择一篇或多篇；不得自行选用没有正文使用依据的作品。
2. 目标项目已存在时直接使用。目标是全新长篇且项目尚不存在时，先按 `项目定位.md` 执行“范文驱动预初始化”：确认暂定书名、主类型和安全目录名，建立最小项目壳；不得先编造总大纲。
3. 将选定文件、参考维度和禁止复用项写入目标项目根目录 `参考素材.md`。
4. 读取范文正文、拆书报告、目标项目已有 `novel-config.md` 与 `plan/`；使用提示词生成 `plan/范文迁移方案.md`。局部正文范文必须同时读取其实际章节范围和禁止推断项。
5. 迁移方案只能保留抽象层机制，例如钩子原理、节奏密度、情绪波形、角色功能、冲突升级方式；不得复用原作专名、独特设定、具体人物关系、标志场景、事件顺序、台词或表达。
6. 完成原创性闸门：以下五项至少重新设计四项：人物与关系、核心冲突、事件因果链、反转机制、结局选择。五项高度相同，或任意三项存在可一一映射的连续对应时，结论为“应重构”，暂停大纲和正文生成。
7. 迁移方案确认后进入“大纲生成”；候选内容先在会话中生成，需要中断或跨会话复查时只写入 `plan/总大纲_待原创性复查.md`，不得提前占用正式总大纲文件名。
8. 二次原创性复查通过后才写入 `plan/总大纲.md`，补齐 `novel-config.md` 和主角状态仓库，并将项目状态从“待生成总大纲”改为“总大纲已确认”；复查失败时保留候选文件并标记“应重构”，不得写正式总大纲、黄金三章、细纲或正文。

### 2.8 多范文重组

- 每个关键机制注明来自哪篇范文、只参考什么抽象维度。
- 不得把 A 的人物关系、B 的事件链和 C 的结局直接拼接成换皮故事。
- 先合并为“机制候选池”，再围绕新作的一句话卖点、核心价值和目标读者重新选择。
- 冲突机制互斥、平台节奏不兼容或目标读者不同的部分必须舍弃，不强行融合。

### 2.9 归档边界

- 范文资产：`<长篇范文库>/<平台>范文/<大类题材>/《作品名》/`。
- 项目选材记录：`<小说项目>\参考素材.md`。
- 项目原创迁移决策：`<小说项目>\plan\范文迁移方案.md`。
- 正式总大纲、细纲、黄金三章、正文和总结仍使用现有长篇工作流；范文报告与迁移方案不能替代正式大纲。

## 三、文风蒸馏与执行

> 适用范围：MyNovel 长篇分支。
> 本文件把范文文风蒸馏、项目文风确定、正文执行与文风校准的运行规则固化下来。先读本文件，再读对应提示词。

### 3.1 概念

| 名称 | 归属 | 作用 | 是否含原文例证 |
|---|---|---|---|
| 拆书报告 | 范文 | 题材、人物、剧情、爽点、结构和市场机制 | 可含少量定位证据，不大段引用 |
| 文风统计报告 | 范文 | 确定性统计结果 | 不含大段原文 |
| 文风分析报告 | 范文 | 对语言和叙事规律进行带证据解释 | 可含必要短例证和章节定位 |
| 文风基因 | 范文 | 将稳定规律压缩为可复用抽象参数 | 禁止出现原句、专名和独特意象 |
| 项目文风规范 | 小说项目 | 当前项目唯一可执行的文风权威源 | 禁止出现来源原句 |
| 文风校准记录 | 小说项目 | 记录版本变更、偏移和人工反馈 | 只引用项目自身正文位置 |
| 正文自然化阶段 | Skill | 在正式审查前进行低改动表达整理 | 不绑定具体范文 |

#### 冲突优先级

正文生成、审查和修复出现冲突时，严格按以下顺序处理：

```text
用户本次明确要求
> 已发生正文事实、状态仓库与信息边界
> 本章正式细纲和后续两章边界
> 角色性格规格卡与角色说话方式
> 项目文风规范中的硬规则
> 正文自然化阶段
> 项目文风规范中的软倾向
```

文风不能成为修改事实、提前消耗后续事件、增加角色或改变金手指规则的理由。

#### 唯一权威源

- 范文文风的证据权威：`正文.txt` + `章节索引.md` + `文风统计报告.md`。
- 范文抽象文风资产：`文风基因.md`。
- 单本小说当前执行文风：`创作依据/文风规范.md`。
- `novel-config.md` 只保存文风入口、状态、版本、生效章节和少量核心约定，不复制完整规范。
- `参考素材.md` 只记录选择了哪些范文、参考哪些维度和禁止复用项，不复制完整文风基因。

### 3.3 文风蒸馏工作流

#### 路由

- 路由名称：`文风蒸馏`。
- 触发语：文风蒸馏、提炼这本范文的文风、生成文风基因、分析范文语言风格、更新文风档案。
- “拆书”默认不自动执行文风蒸馏；用户明确要求“拆书并蒸馏文风”时可以连续执行两个工作流。

#### 前置条件

1. 范文必须存在 `元数据.md`、`正文.txt` 和 `章节索引.md`。
2. 正文必须具有现有范文流程要求的合法使用依据。
3. 章节索引必须能够可靠定位连续章节。
4. 文风蒸馏只分析实际读取的文本，不推断未读章节。
5. 文风样本字数按规范化后的中文字符和标点统计。

#### 样本等级

| 样本条件 | 等级 | 允许输出 |
|---|---|---|
| 少于 8000 字或只有单一场景 | 不足 | 只输出缺口，不生成正式文风基因 |
| 8000-19999 字，覆盖至少 3 个样本块 | 初步 | 可生成 `初步文风基因`，不得用于正式项目冻结 |
| 20000 字以上，覆盖至少 5 类场景和 3 个非相邻章节块 | 正式 | 可生成正式文风基因 |
| 40000 字以上，完成保留样本验证 | 已验证 | 可标记验证通过 |

默认从现有连续正文范围中分层取样，不要求为了文风蒸馏读取全部 50 章。建议覆盖：

1. 黄金三章或开篇样本；
2. 对话密集场景；
3. 动作、冲突或爽点兑现场景；
4. 日常、转场或信息投放场景；
5. 情绪、关系或心理场景；
6. 中后段用于检查文风漂移的非相邻样本。

缺少某类场景时必须写明，不得由模型虚构该场景的文风规律。

#### 保留样本

达到正式样本等级时，从可用文本中保留约 20% 的章节块，不参与初感受、深度分析和基因生成。文风基因生成后，再用保留样本验证：

- 规范是否能解释保留样本的句段、对白、叙事距离和场景节奏；
- 是否把偶然表达误写为稳定规律；
- 是否漏掉跨章节稳定特征；
- 是否出现与保留样本相反的硬规则。

验证失败时修改分析和基因，不能修改保留样本或降低标准来制造通过。

#### 七阶段执行

##### 阶段 1：样本计划

根据 `章节索引.md` 生成本次样本计划，记录章节、场景类型、纳入原因、训练样本或保留样本身份。样本计划写入 `文风分析报告.md` 开头，不另建无必要文件。

##### 阶段 2：确定性统计

运行 `文风统计.py`，生成 `文风统计报告.md`。统计结果只能描述可计算事实，不能直接推断文学效果。

```powershell
<python3> "<Skill根目录>/scripts/文风统计.py" profile `
  --text <正文.txt> `
  --index <章节索引.md> `
  --chapters <章节选择表达式> `
  --output <文风统计报告.md>
```

##### 阶段 3：定性初感受

先整体感受、后拆解。定性观察只能形成候选判断，不能直接进入硬规则。

##### 阶段 4：多维证据分析

至少覆盖：

1. 整体体感与叙事温度；
2. 叙事视角、聚焦人物和叙事距离；
3. 句长、句式、段落和换气；
4. 词汇语域、动词密度、连接方式和口语程度；
5. 对话长度、潜台词、动作标签和角色辨音；
6. 动作链与冲突呈现；
7. 心理描写的直接与间接程度；
8. 环境、感官和物件描写的功能；
9. 比喻、修辞、评价句和作者介入；
10. 场景推进、转场、信息投放和章末落点；
11. 不同场景下的变化规律；
12. 反模式、模型容易误学的表面特征和样本盲区。

每项先写统计证据和章节证据，再写解释，再标置信度。不得只输出“文笔自然、节奏明快、语言生动”等无执行价值评价。

##### 阶段 5：文风基因蒸馏

将分析压缩为 `文风基因.md`。删除全部原文例证、专名、独特意象和具体事件，只保留抽象规则、使用条件、置信度和风险。

来源作品的统计倾向默认是软倾向。只有视角、明显禁用标点等稳定且可验证特征，才能成为来源硬候选；真正的项目硬规则必须在项目文风编译阶段由用户或项目决策确认。

##### 阶段 6：保留样本验证

按“保留样本”执行。输出“通过 / 初步通过 / 失败待重做”及具体偏差。

##### 阶段 7：归档与复读

更新 `元数据.md` 的文风字段，复读：

- 元数据文风状态；
- 文风样本范围和对应正文版本；
- 文风统计报告；
- 文风分析报告；
- 文风基因；
- 保留样本验证结论。

任一版本对不上，不得报告蒸馏完成。

### 3.4 项目文风确定工作流

#### 路由

- 路由名称：`项目文风确定`。
- 触发语：给新书确定文风、使用这几本范文的文风、融合文风基因、生成项目文风规范、修改这本书后续文风。

#### 三种模式

##### 单范文

选择一个状态为正式或已验证的 `文风基因.md`，但仍需编译为项目文风规范。不得直接复制来源文风基因作为项目文件。

##### 多范文融合

不得用模糊百分比把整本书机械混合。应按维度指定来源，例如：

```text
叙事距离：来源 A
对白节奏：来源 B
动作场景：来源 A
日常过渡：来源 C
章末落点：项目原创
```

来源规则冲突时必须选择、改写或舍弃，不能同时保留互斥规则。最终规范必须读起来像同一个叙述者，而不是多个范文轮流出现。

##### 无范文原创

通过项目类型、平台、目标读者、叙事视角、节奏偏好、对白偏好和用户自有样章生成原创项目文风。仍然生成同结构的 `项目文风规范.md`，来源写“无范文原创”。

#### 新项目要求

新建长篇项目时，必须明确选择一种文风模式，但不强制必须选择范文。文风决策应在正式总大纲生成前完成。

如果用户暂时不确定，可将 `文风状态` 设为 `待选择`，但不得进入正式正文生成。可以先进行选题、金手指方案和候选大纲讨论，正式总大纲落盘前必须完成项目文风规范。

#### 项目文风编译闸门

输入包括：目标平台和类型、用户明确偏好、选定范文的 `文风基因.md`、`参考素材.md` 中的参考维度和禁止复用项、项目角色规格卡、如已有正文则项目自身最近代表章节。

输出 `创作依据/文风规范.md`，并执行以下闸门：

1. 不包含来源原句、专名、独特比喻和具体事件。
2. 不包含"像某某作者一样写""化身作者""作者替身"等身份模仿指令。
3. 每条硬规则可执行、可审查、存在明确适用范围。
4. 场景模式分别描述，不使用全书固定描写比例机械约束每章。
5. 与角色规格卡冲突时，以角色规格卡为准并在规范中明确。
6. 与项目类型和平台承诺冲突时，重构项目文风，不照搬来源。
7. `写前速查` 控制在 8-12 条，避免正文上下文过载。

#### 原创性闸门

项目文风迁移只允许使用句法、节奏、叙事距离、描写功能、对白组织和场景呼吸等抽象机制。继续沿用现有原创仿写闸门，并额外禁止：

- 来源作品连续表达和近似改写；
- 独特比喻系统中的具体喻体；
- 来源作品标志性口头禅；
- 可识别的独特句式与独特意象组合；
- 为了“像来源作品”而复现相同场景和情绪顺序。

#### 确认与冻结

项目文风规范生成后先标记 `已确认`。完成至少一章项目原创校准样章并通过人工确认后，可标记 `已冻结`。

冻结不是永不修改，而是任何修改必须：

1. 版本号递增；
2. 在 `文风校准记录.md` 记录原因和差异；
3. 写明新版本生效章节；
4. 默认不追溯重写旧章节。

### 3.5 大纲、正文、审查与修复集成

#### 大纲生成

总大纲生成前读取 `novel-config.md` 的文风配置和 `项目文风规范.md`。大纲只吸收会影响场景组织的文风约定，例如：

- 视角和聚焦人物；
- 单章场景数量倾向；
- 对话驱动或动作驱动倾向；
- 信息投放方式；
- 章末落点类型；
- 情绪场景需要的留白空间。

不得在大纲中复制完整文风规范，也不得让文风规则新增剧情事件。

#### 分阶段细纲与黄金三章

细纲可以增加以下可选字段：

```markdown
- 场景文风模式：对话 / 动作冲突 / 日常过渡 / 情绪关系 / 信息说明
- 本章文风重点：从项目文风规范选择 1-3 项
- 本章避免项：与当前场景最相关的 1-2 项
```

这些字段只控制表达方式，不改变既有核心事件、角色、爽点或章末钩子。

#### 上下文组装

采用文风系统的项目，在正文生成、草稿审查和自动修复前必须读取：

- `novel-config.md` 的文风配置；
- `创作依据/文风规范.md`；
- `创作依据/文风校准记录.md` 中当前版本之后仍有效的人工校准项，如文件存在。

上下文组装时提炼一个“本章文风执行表”，只包含：

- 当前文风版本；
- 本章场景模式；
- 适用硬规则；
- 最相关的软倾向；
- 角色说话方式覆盖项；
- 本章高风险表达；
- 禁止加载的来源文件确认。

不得把完整范文文风分析报告和范文正文装入正文上下文。

#### 正文生成

在现有事实锁和写前校准之后增加“文风校准闸门”：

1. 项目配置为 `已确认` 或 `已冻结` 时，项目文风文件必须存在且版本一致。
2. 本章场景模式必须能映射到项目文风规范。
3. 若项目文风与角色规格卡冲突，明确采用角色规格卡。
4. 若项目文风要求会导致大纲外扩写，放弃该要求，不新增事件。
5. 生成时只输出正文；不得在正文后附“风格执行自查”。

正文生成后先运行字数统计，再运行通用质检和原文重合检查。重合检查命中阻断阈值时必须局部改写并复查，不能删除大纲核心事件来规避。

#### 草稿审查

草稿审查新增独立的“项目文风一致性”检查，与正文自然化阶段分工。

审查只报告具有正文证据和修改价值的偏移：

- 硬规则违反；
- 叙事视角或距离漂移；
- 同类场景连续偏离项目场景模式；
- 角色规格卡被全书文风覆盖；
- 通用模型模板重新出现；
- 与来源范文存在连续文本重合风险。

单个句子没有命中软倾向，不构成问题。不得为了追求统计完全一致，把正文机械修成平均值。

审查报告增加：

```markdown
## 文风执行核对
- 项目文风版本：
- 场景模式匹配：通过 / 偏移
- 硬规则：通过 / 违反
- 软倾向整体一致性：稳定 / 轻微漂移 / 明显漂移
- 角色声音优先级：通过 / 被项目文风覆盖
- 原文重合检查：通过 / 需复核 / 阻断
- 证据位置：
```

#### 自动修复

文风修复遵守最小修改原则：

1. 只修审查确认的问题段落。
2. 不改变事件、信息、人物选择、时间线和资源结算。
3. 不为了接近统计值批量替换全章句式。
4. 修复角色台词时先服从角色规格卡，再服从项目文风。
5. 修复后重新运行字数、通用质检和原文重合检查。
6. 若修复需要改变场景结构或事件顺序，标记高风险并停止自动修复。

#### 文风漂移校准

出现以下任一情况时进入 `文风校准`：

- 用户明确认为近期正文变得像 AI；
- 连续三章出现同类文风偏移；
- 更换主要生成模型；
- 进入叙事方式明显变化的新阶段；
- 用户提供新的自有样章或人工修改稿；
- 项目决定更换或融合新的来源文风。

校准优先从项目自身已确认正文和人工修改差异中提炼规则，不重新加载来源范文原文。只有用户明确要求调整来源文风时，才回到“项目文风确定”工作流。

### 3.6 脚本证据与失败处理

- `文风统计.py` 只输出统计，不输出文学判断。统计报告用于支撑文风分析报告的证据等级。
- `原文重合检查.py` 用于检查草稿与来源范文的连续文本重合。重合检查命中阻断阈值时，正文流程必须局部改写并复查。
- 脚本失败时不得伪造统计结果。应标注未使用脚本，并停止正式文风蒸馏；正文阶段的重合检查失败也应报告风险，不得声称通过。
- 临时重合检查报告默认不进入小说长期上下文；审查报告只记录结论和必要位置。
