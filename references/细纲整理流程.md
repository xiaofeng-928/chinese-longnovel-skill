# 细纲整理流程

把手写、笼统或格式不统一的 50 章以内细纲整理为可执行计划，不改写用户已经确定的核心事件。

1. 按 `references/项目定位.md` 定位项目并运行结构验证。
2. 读取 `novel-config.md`、`plan/总大纲.md`、当前 `plan/大纲_第X-Y章.md`、同范围 `plan/系统发展_第X-Y章.md`、`设定/角色档案.md`、`plan/伏笔追踪.md` 和 current head 可达的必要上下文。
3. 使用 `prompts/分阶段大纲细化提示词.md` 的“整理既有细纲模式”，一次不超过 50 章。
4. 每个主章写入唯一 `MYNOVEL:PLAN-NODE` 块：`node_id`、`planned_main_chapter`、`node_type`、`mainline_anchor`、`plan_status`、`task_refs`。不得把运行态写入 plan。
5. 系统商品、任务、预算、经营循环或成长路线有缺口时，先补 `plan/系统发展_第X-Y章.md`；不得在剧情细纲中临时发明系统规则。
6. 整理后运行 `scripts/validate_project.py`。只替换目标节点块，不覆盖其他章节或 current head 投影。

输出整理后的细纲、发现的上游冲突和验证结果；无冲突时不单独输出“修改建议及技法应用”。这些内容属于后续正文审查与修复。
