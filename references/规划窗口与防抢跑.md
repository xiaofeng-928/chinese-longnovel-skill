## 职责

在每个最多 50 章的剧情细纲生成前，完成金手指准备、宏观阶段扩窗、剧情预算锁定和 manifest 指针更新，防止当前窗口提前完成宏观阶段、透支后续窗口或借用下一宏观阶段内容。

## 术语与权威

- **宏观阶段**：`plan/总大纲.md` 中的 `MYNOVEL:STAGE` 块，通常覆盖 150-300 章。
- **规划窗口**：一次最多 50 章的计划单元，对应 `plan/系统发展_第X-Y章.md` 和 `plan/大纲_第X-Y章.md`。
- **窗口合同**：总大纲中的 `MYNOVEL:WINDOW` 块，规定当前窗口能完成、只能推进、禁止提前完成和必须留给后续窗口的内容。
- **剧情预算锁**：`novel-config.md` 中绑定窗口合同的 `locked` 状态。未锁定不得生成同范围细纲。
- 主角/系统状态仓库仍是正文已发生事实；窗口合同、系统发展和细纲都是计划态，不得提前写入运行态仓库。

## 强制顺序

对目标窗口 `第S-E章` 必须按以下顺序执行，不得跳步或倒置：

1. 读取当前 committed 正文、章节总结和主角/系统状态仓库，确定期初真实状态。
2. 审核 `设定/系统设定.md` 是否足以支持目标窗口；需要新增永久规则、商品、权限、任务类型或成长分支时，先完成系统设计更新和版本递增。
3. 生成同范围 `plan/系统发展_第S-E章.md`，明确本窗口系统目标、禁止提前解锁项和留给后续窗口的成长内容。
4. 使用 `prompts/规划窗口准备提示词.md` 扩展总大纲：首次进入某宏观阶段时，一次拆出该宏观阶段全部连续窗口合同；当前窗口再补齐五章剧情预算。
5. 更新 `novel-config.md` 的当前/下一窗口合同和剧情预算锁。配置只保存 ID、状态和路径，不复制剧情正文。
6. 前五步验证通过后，才使用 `prompts/分阶段大纲细化提示词.md` 生成细纲。
7. 细纲末尾执行防抢跑自检；任一项失败，先修订细纲，不得把风险版归档。

## 金手指准备边界

- 永久设计更新只写确认后的规则和允许空间，不写未来余额、已完成任务或已获得模块。
- 系统发展文件负责目标窗口内的资源预算、任务池、商店、成长和验证节奏。
- 系统发展文件必须输出四类边界：`本窗口可完成`、`只推进不完成`、`禁止提前解锁/结算`、`后续窗口保留`。
- 当前窗口无法在不违反永久设计的前提下成立时，标记 `structural` 并退回系统设计；不得靠细纲临时发明功能。

## 宏观阶段扩窗规则

- 首次为某宏观阶段准备细纲时，必须把该阶段从 `chapter_start` 到 `chapter_end` 拆成连续、无重叠、每段不超过 50 章的窗口合同；不能只规划眼前 50 章而把后续留空。
- 每个宏观阶段必须有非空 `exit_condition`。只有最后一个窗口允许 `stage_exit_allowed: true`。
- 非最后窗口必须保留未解决矛盾和后续专属剧情；不得完成宏观阶段核心目标、退出条件或下一阶段入口事件。
- 每个窗口必须拥有独立功能和可结算成果，但该成果只能消耗分配给本窗口的预算。
- 关键事件、角色转变、系统跃升和伏笔回收必须按计划章号归属窗口；不得为了让当前窗口更完整而前移。
- 当前窗口合同必须按每 5 章建立剧情预算；未来保留窗口只需先锁定窗口级预算，轮到该窗口时再补齐五章预算。

## 总大纲窗口合同 schema

窗口块放在 `MYNOVEL:STAGE` 块之外，统一置于总大纲的“规划窗口合同”部分，避免嵌套锚点干扰阶段解析。

```markdown
<!-- MYNOVEL:WINDOW:window-0051-0100:START -->
- window_id: window-0051-0100
- stage_id: stage-0002
- chapter_start: 51
- chapter_end: 100
- window_status: prepared
- stage_exit_allowed: false
- system_plan: plan/系统发展_第51-100章.md
- must_complete: 本窗口必须完整结算的事件或状态
- advance_only: 本窗口只能推进、不得完成的宏观任务
- protagonist_progress_cap: 本窗口末主角身份、能力、资源、关系和地图推进的计划上限
- system_progress_cap: 本窗口末系统等级、权限、商品、任务和资源额度的计划上限
- forbidden_early_completion: 禁止提前完成的阶段目标、退出条件、解锁和伏笔
- reserved_for_later: 明确留给后续各窗口的剧情负载
- end_unresolved: 窗口末必须仍然存在的矛盾、债务或行动目标
- next_stage_forbidden: 当前窗口禁止使用的下一宏观阶段内容
- next_window_id: window-0101-0150
- five_chapter_budget_status: locked

## 五章剧情预算
| 五章组 | 本组职责 | 允许结算 | 禁止越过 | 必须留给后组 |
|---|---|---|---|---|
| 第51-55章 | ... | ... | ... | ... |
<!-- MYNOVEL:WINDOW:window-0051-0100:END -->
```

- `window_status`：`reserved / prepared / active / consumed / superseded`。
- `five_chapter_budget_status`：未来窗口可为 `pending`；准备生成细纲的窗口必须为 `locked` 并具备“五章剧情预算”表。每行除章号外的“本组职责、允许结算、禁止越过、必须留给后组”四格都必须写入具体内容，不得留空或使用省略号、字段名、`TODO/TBD/待定` 等占位文本。
- `prepared / active` 目标窗口的 `system_plan` 必须指向已经存在的同范围文件；尚未轮到的 `reserved` 未来窗口统一写 `system_plan: null`，不得预填不存在的路径。
- 非最后窗口的 `reserved_for_later`、`forbidden_early_completion`、`end_unresolved` 不得为空或写成 `[]`。
- `protagonist_progress_cap` 与 `system_progress_cap` 是未来计划上限，不是运行态快照；细纲不得越过，也不得提前写入状态仓库。
- 最后窗口的 `next_window_id` 为 `null`；其他窗口必须指向同一宏观阶段的下一连续窗口。

## novel-config 窗口字段

完成窗口准备时增加或更新：

```markdown
- 规划窗口协议版本：1
- 当前窗口合同：window-0001-0050
- 当前剧情预算锁：locked
- 下一窗口合同：window-0051-0100
- 下一剧情预算锁：locked
```

- 合同 ID 必须与 `当前计划窗口`、`下一计划窗口` 的章号范围一致。
- 尚未准备下一窗口时，下一合同和下一预算锁均为 `null`。
- 若正文正在使用当前窗口而提前规划后续窗口，只更新“下一”字段；不得覆盖当前正文所依赖的计划指针。
- 准备目标窗口时，对应的当前/下一计划窗口范围与系统计划路径必须同时写入；剧情细纲路径在文件生成并验证前保持 `null`，成功后再登记。
- 切换计划窗口时，合同 ID、预算锁、系统计划路径和剧情细纲路径必须一起切换。
- 首个当前窗口尚未生成细纲时，`project_status` 保持 `总纲`；细纲文件、PLAN-NODE 和权威路径齐全并验证通过后才晋级 `细纲`。正文中项目提前准备下一窗口时保持 `正文中`，当前路径不变，下一剧情细纲在生成前为 `null`。

## 细纲生成闸门

出现任一情况时停止细纲生成，先返回窗口准备流程：

- 同范围系统发展文件缺失，或系统设计仍有 `structural` 问题。
- 目标范围没有对应窗口合同，合同章号、阶段 ID 或 config 指针不一致。
- `five_chapter_budget_status` 或 config 剧情预算锁不是 `locked`。
- 宏观阶段没有退出条件，或非最后窗口被允许完成退出条件。
- 后续窗口没有保留剧情负载，无法证明剩余内容足以支撑剩余章数。

## 兼容旧项目

- 未启用 `规划窗口协议版本：1` 的旧项目可以继续读取和创作已有正式细纲。
- 旧项目第一次请求生成新的 50 章细纲前，必须补做窗口准备；不得直接沿用旧流程生成。
- 回填合同只总结已有总纲和正式细纲，不擅自改写已确认事件；发现宏观阶段本身内容不足时先报告结构问题并扩充总纲，再锁定窗口。
