# 自动化脚本契约

## 职责

规定未来 MyNovel Skill 内置脚本的文件名、用途、调用方式和输出用途。

## 脚本目录

通用脚本放在：

```text
C:\Users\Lenovo\.claude\skills\MyNovel\scripts\
```

单本小说专属导出脚本仍放在小说项目目录，例如 `convert_to_epub.py`。

## 已实现脚本

- `小说质检.py`：字数统计（省略号加权口径）、AI味三梯队词、禁用词、关键时间锚候选、能力解锁候选扫描。
- `count_chars.py`：审查字数统计 CLI，口径与 `小说质检.py` 一致。
- `文风统计.py`：范文正文确定性文体统计（总字符/章节/句子/段落数、句长与段长分位数、对话占比、标点频率、词类频率、同构句与重复短语候选、按章节统计）。
- `原文重合检查.py`：草稿与来源范文的连续字符重合检查，支持多来源和白名单，输出含标点与去标点两种口径，阈值集中定义。
- `项目事务.py`：项目 manifest 解析与校验、单写者锁、genesis/commit-head 链、不可变事务、投影重建与 head CAS 恢复算法。模块，非独立 CLI。
- `validate_project.py`：项目结构验证器，检查 manifest schema、权威路径存在性、commit head 链、plan 过期运行态、HTML 锚点、状态仓库拆分声明和重复权威块。

## 调用原则

- 脚本是普通本地命令行工具，不依赖隐藏 hook。
- Claude Code、Codex 和子 agent 都通过 shell 调用脚本。
- 脚本存在且适用时，优先使用脚本输出作为证据。
- 脚本不存在时，不临时创建替代脚本；在报告中注明未使用脚本。
- 脚本输出可写入审查报告、验证结论和修复记录。
- 脚本负责输出事实和证据，不负责判断模糊用户意图。模糊定位、取舍和追问仍由 Agent 完成。
- 默认输出 JSON；需要可读报告时可加 `--format markdown`。

## 命令契约

### 小说质检.py

用途：字数、AI味三梯队、禁用词、时间锚候选、能力/资源候选扫描。

### 文风统计.py

用途：对范文正文做确定性文体统计，只输出可计算事实，不输出文学判断。文风蒸馏时按 `文风蒸馏与执行流程.md` 的样本计划分层取样后调用。

```powershell
python C:\Users\Lenovo\.claude\skills\MyNovel\scripts\文风统计.py profile --text <正文.txt> --index <章节索引.md> --chapters <章节选择表达式> --output <文风统计报告.md>
py -3 C:\Users\Lenovo\.claude\skills\MyNovel\scripts\文风统计.py profile --text <正文.txt> --index <章节索引.md> --chapters 1-3,8-10
```

关键输出：`total`（chars/chapters/sentences/paragraphs/对话占比）、`sentence_lengths` 与 `paragraph_lengths`（mean/p25/median/p75/p90）、`punctuation`（逗号/句号/问号/感叹号/省略号/破折号频率）、`word_classes`（连接词/反应词/程度副词/转场词频率）、`candidates`（同构句与重复短语候选）、`chapters`（按章节分别统计）。

### 原文重合检查.py

用途：检查草稿与来源范文之间的连续字符重合，支持多来源。只检测规范化后的连续字符重合，不判定语义近似抄袭。阈值集中定义并配有单元测试。

```powershell
python C:\Users\Lenovo\.claude\skills\MyNovel\scripts\原文重合检查.py check --draft <草稿文件> --source <范文正文.txt> --output <临时检查报告.md>
python C:\Users\Lenovo\.claude\skills\MyNovel\scripts\原文重合检查.py check --draft <草稿文件> --source <范文A正文.txt> --source <范文B正文.txt> --whitelist <白名单文件>
py -3 C:\Users\Lenovo\.claude\skills\MyNovel\scripts\原文重合检查.py check --draft <草稿文件> --source <范文正文.txt>
```

阈值：连续重合 16-23 个中文字符为 `需复核`；24 个及以上为 `阻断`；12-15 个中文字符只有在同一表达重复命中两次以上时才报告。专名、系统固定提示和类型公共术语可通过白名单豁免，但必须在输出 `exempted` 中记录。多来源用重复 `--source` 传入。临时重合检查报告默认不进入小说长期上下文；审查报告只记录结论和必要位置。

### validate_project.py

用途：项目结构验证器。在项目定位、迁移、一致性检查、正文生产前运行，提供确定性结构事实。

```powershell
python C:\Users\Lenovo\.claude\skills\MyNovel\scripts\validate_project.py --project-root D:\ai小说\小说\<项目>
py -3 C:\Users\Lenovo\.claude\skills\MyNovel\scripts\validate_project.py --project-root D:\ai小说\小说\<项目> --json
```

关键输出（JSON）：`ok`、`checks.manifest`、`checks.authority`、`checks.plan`、`checks.anchor`、`checks.chain`、`checks.duplicate_authority`。退出码 `0=通过`、`1=未通过`。覆盖以下确定性问题：

- manifest 是否缺少必填键、schema 是否合法、`project_id` 是否为 UUID v4、权威路径是否越出项目根。
- 当前生命周期与系统模式声明的权威文件是否真实存在（文档 3.7 的断链回归）。
- plan 文件是否携带“已发布章节/当前写到”等过期运行态（文档 3.8）。
- HTML 锚点是否重复或未配对（文档 9.4）。
- commit head 是否能沿 `parent_transaction_id` 无环回到 genesis，project_id 是否一致。
- 文风、系统、角色、世界观是否出现重复权威块。

### 项目事务.py

用途：vNext 项目 schema 与原子提交的共享模块，不独立运行。提供 `parse_manifest`、`validate_manifest`、`WriteLock`、`create_genesis`、`read_head`、`prepare_transaction`、`chain_parents`、`verify_chain`、`commit_head_cas`。正文生产、状态总结和 EPUB 导出都通过它获得当前 head 与写锁，禁止绕过该模块直接改 `commit-head.json`。

## 审查证据写入规则

### 扫榜.py

“扫榜.py”只处理已取得的结构化榜单记录，生成题材候选和选题决策文档。网络抓取、登录态和平台反爬由外部工具或用户提供的数据负责；脚本不伪造当前热度，也不替用户自动拍板。

- 输出写入扫榜归档目录 `D:\ai小说\扫榜归档`，文件名 `YYYY-MM-DD_平台_选题决策.md`（平台统一为“番茄”/“起点”，多平台用空格连接）；也可用 `--output` 指定完整路径。
- 生成的文档包含五个字段：扫榜元数据、题材候选、推荐结论、来源与证据、范文候选。
- 审查报告中引用脚本结果时，写明脚本名、命令目的和关键 JSON 字段。
- `小说质检.py` 的输出是字数、禁用词、时间锚候选和能力/资源候选的优先证据。
- 未传入 `--forbidden-words` 时，脚本必须输出 `FORBIDDEN_WORDS_NOT_CONFIGURED` 警告；空匹配不能解释为禁用词检查通过。
