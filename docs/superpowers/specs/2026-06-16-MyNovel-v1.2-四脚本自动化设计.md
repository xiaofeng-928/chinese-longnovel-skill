# MyNovel v1.2 四脚本自动化设计

## 目标

v1.2 的目标是在 v1.1 “SKILL.md 拆分为入口路由 + references”的基础上，实现四个可独立调试的本地脚本，把高频、确定性、体力型检查从提示词中移出。

本轮实现四个中文入口脚本：

- `小说文件.py`
- `小说锚点.py`
- `小说质检.py`
- `小说上下文.py`

脚本只负责事实发现、结构化输出和安全文件操作，不负责最终解释用户模糊意图，也不做文学审美判断。模糊指令由 Agent 理解和消歧，脚本提供候选、证据和可复现结果。

## 当前基线

- 当前版本标签：`v1.1`
- v1.1 内容：重构第一步，拆分 `SKILL.md` 为入口路由、中文 `references/` 和脚本契约。
- 系统默认 Python：3.9.13
- Codex 自带 Python：3.12.13
- `pytest`：未安装
- v1.2 脚本约束：使用 Python 3.9 兼容语法，只依赖标准库，测试使用 `unittest`。

## 设计原则

1. 四个脚本使用中文入口名，方便 Agent 和用户理解。
2. 公共逻辑集中到共享模块，避免四个脚本重复实现路径解析、JSON 输出和章节解析。
3. 默认输出 JSON，供 Agent 稳定读取；可选输出 Markdown，供人工查看。
4. 写入类操作必须支持 `--dry-run`。
5. 脚本必须可脱离 Agent 单独运行，便于调试。
6. 脚本不做模糊意图最终裁决，只返回候选和证据。
7. 真实目录结构优先于理想目录结构，必须兼容现有《大医无双》项目。
8. 第一版只做确定性功能，不做复杂自然语言理解。

## 脚本一：`小说文件.py`

### 职责

负责项目、章节、文件路径和 50 章归档段的确定性发现。

### 子命令

#### `scan-projects`

扫描小说工作区，查找包含 `novel-config.md` 的项目。

示例：

```powershell
python scripts/小说文件.py scan-projects --root D:\ai小说 --query 大医无双
```

输出：

- 项目路径
- 项目名
- `novel-config.md` 路径
- 匹配分数
- 匹配原因

#### `chapter-status`

检查某个章节范围内正文文件状态。

示例：

```powershell
python scripts/小说文件.py chapter-status --project D:\ai小说\小说\都市-大医无双 --range 1-30
```

输出：

- 已存在章节
- 缺失章节
- 草稿/已审查/正式稿状态
- 同章多文件冲突
- 最高已写章节

#### `archive-path`

计算指定章节的 50 章归档文件路径。

示例：

```powershell
python scripts/小说文件.py archive-path --project D:\ai小说\小说\都市-大医无双 --chapter 61 --type summary
```

输出：

- 起始章
- 结束章
- 归档文件路径
- 归档类型

### 边界

`小说文件.py` 可以返回“大医无双”匹配候选，但不直接决定用户真实意图。Agent 根据候选结果继续判断或询问用户。

## 脚本二：`小说锚点.py`

### 职责

负责检查和安全替换 HTML 锚点块，防止重复追加或覆盖同一 50 章归档文件中的无关章节。

### 子命令

#### `check`

检查指定文件中的锚点状态。

示例：

```powershell
python scripts/小说锚点.py check --file D:\ai小说\小说\都市-大医无双\章节总结\章节总结_第1-50章.md --chapter 22 --kind summary
```

输出：

- start 锚点数量
- end 锚点数量
- 是否重复
- 是否缺失
- 目标块行号范围

#### `replace`

替换指定锚点块。默认必须显式传入 `--content-file`，避免命令行转义大段正文。

示例：

```powershell
python scripts/小说锚点.py replace --file D:\path\章节总结_第1-50章.md --chapter 22 --kind summary --content-file D:\tmp\chapter22-summary.md --dry-run
```

输出：

- 是否会替换
- 是否会追加
- 修改前后摘要
- `dry_run` 状态

### 锚点格式

第一版支持当前提示词中的格式：

```text
<!-- chapter:X summary:start -->
<!-- chapter:X summary:end -->
<!-- chapter:X review:start -->
<!-- chapter:X review:end -->
```

### 边界

`小说锚点.py` 不生成总结、不判断审查问题，只负责锚点安全。

## 脚本三：`小说质检.py`

### 职责

负责正文的量化质检，输出可复现证据。

### 子命令

#### `lint`

对单个正文文件或多个正文文件做质检。

示例：

```powershell
python scripts/小说质检.py lint --file D:\ai小说\小说\都市-大医无双\正文\第022章_xxx.md --format json
```

### 第一版检查项

#### 字数统计

口径：

- 汉字算 1
- 数字算 1
- 英文字母算 1
- 中文标点算 1
- 英文标点算 1
- 空格不算
- 制表符不算
- 换行不算
- 空行不算

实现口径：统计所有非空白字符数。

#### AI味三梯队

第一梯队：任一词出现大于等于 2 次就报。

- 不由得
- 情不自禁
- 下意识
- 本能地

第二梯队：累计大于 3 次就报。

- 震惊
- 不可思议
- 倒吸一口凉气
- 瞳孔骤缩
- 面色大变
- 全场鸦雀无声
- 空气凝固
- 时间仿佛静止

第三梯队：累计大于 5 次就报。

- 微微
- 淡淡
- 缓缓
- 默默
- 轻轻
- 深深

#### 时间锚候选

抽取包含时间表达的句子，作为 Agent 判断关键时间锚的候选。

第一版只做候选，不判断是否关键。

候选词包括：

- 今天、昨日、明天、刚才、刚刚、片刻、半小时、一小时、十分钟、二十分钟
- 一年前、一年、数日、三天、七天、期限、倒计时、晚上、清晨、凌晨、中午

#### 能力/资源/解锁候选

抽取包含能力变化、升级、资源变化的句子。

候选词包括：

- 升级、突破、解锁、获得、失去、消耗、恢复、强化、觉醒
- 等级、能力、技能、道具、资源、积分、灵力、真气、系统

#### 禁用词接口

第一版内置空禁用词列表，并支持从外部文本文件读取：

```powershell
python scripts/小说质检.py lint --file chapter.md --forbidden-words 禁用词.txt
```

### 输出

JSON 输出包含：

- `ok`
- `command`
- `inputs`
- `word_count`
- `ai_flavor`
- `forbidden_words`
- `time_anchor_candidates`
- `ability_candidates`
- `warnings`

Markdown 输出用于人工快速查看。

### 边界

`小说质检.py` 只输出数据和阈值命中，不评价剧情质量，不给文学修复方案。

## 脚本四：`小说上下文.py`

### 职责

根据项目和目标章节，输出 Agent 应读取的上下文文件清单。

### 子命令

#### `build`

示例：

```powershell
python scripts/小说上下文.py build --project D:\ai小说\小说\都市-大医无双 --chapter 23 --mode review
```

输出：

- `novel-config.md`
- 最近 3 章正文
- 最近 20 章章节总结所在文件
- 本章大纲归档文件
- 后续 2 章边界大纲所在文件
- 当前阶段总结候选
- 伏笔补读候选提示

### 边界

`小说上下文.py` 第一版只输出“应该读取哪些文件”和“可能需要关注哪些章节”，不拼接全文，不判断伏笔含义。

## 公共模块：`公共工具.py`

负责四个脚本共享的基础能力：

- JSON 输出
- Markdown 输出辅助
- UTF-8 文件读取
- 章节号解析
- 章节范围解析
- 50 章归档段计算
- 项目目录别名识别
- 正文章节文件名解析
- 错误输出格式

## 规则模块：`质检规则.py`

负责可调规则：

- AI味三梯队词表
- 三梯队阈值
- 时间锚候选词
- 能力/资源/解锁候选词
- 默认禁用词列表

后续压缩提示词时，优先把量化规则迁入此文件，提示词只保留“如何使用脚本结果”的说明。

## 调试设计

每个脚本都必须能直接在 PowerShell 中运行。

共同参数：

- `--format json`
- `--format markdown`
- `--verbose`

写入类参数：

- `--dry-run`

错误输出统一为 JSON：

```json
{
  "ok": false,
  "command": "命令名",
  "error": {
    "code": "ERROR_CODE",
    "message": "中文错误说明"
  }
}
```

这样调试时可以区分：

- 脚本输出错误：修脚本。
- 脚本输出正确但 Agent 解读错：修提示词或流程。
- 脚本和 Agent 都正确但用户意图不明确：Agent 询问用户。

## 测试设计

使用标准库 `unittest`，不依赖 `pytest`。

开发必须采用测试驱动：

1. 先写测试。
2. 运行测试，确认失败，且失败原因是功能尚未实现。
3. 写最小实现让测试通过。
4. 再运行测试，确认通过。
5. 每新增一个行为，都重复红灯、绿灯、重构流程。

测试夹具创建一个迷你小说项目：

```text
迷你小说项目/
├── novel-config.md
├── 正文/
│   ├── 第001章_开局.md
│   ├── 第002章_冲突（草稿）.md
│   └── 第002章_冲突（已审查）.md
├── plan/
│   └── 大纲_第1-50章.md
├── 章节总结/
│   └── 章节总结_第1-50章.md
├── 阶段总结/
│   └── 阶段1_开局_1-10章.md
```

## 提示词同步

实现脚本后，同步压缩和修正：

- `prompts/草稿审查提示词.md`
- `prompts/草稿自动修复提示词.md`
- `references/自动化脚本契约.md`

压缩目标：

- 提示词不再完整列出所有量化词表和阈值。
- 提示词改为要求 Agent 运行 `scripts/小说质检.py` 并引用脚本结果。

## 非目标

v1.2 不实现：

- 自动写正文。
- 自动修复正文。
- 大模型调用。
- 复杂自然语言意图理解。
- 复杂伏笔语义判断。
- 自动拼接完整上下文大文本。
- EPUB 导出。

## 验收标准

- 四个中文入口脚本存在并可运行。
- 公共模块和规则模块存在。
- 所有脚本兼容 Python 3.9。
- 所有脚本只依赖标准库。
- `python -m unittest` 通过。
- `小说质检.py` 字数统计符合本设计口径。
- `小说锚点.py replace --dry-run` 不修改文件。
- `小说文件.py` 能检测同章多文件。
- `小说上下文.py` 能输出上下文文件清单。
- 审查/修复提示词不再指向旧工作区脚本目录。
- 桌面 `MyNovel提示词字数基线.txt` 可用于后续记录压缩后数据。
