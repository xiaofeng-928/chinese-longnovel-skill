# MyNovel 金手指设计能力改造方案

> 状态：设计稿，尚未实施  
> 日期：2026-08-05  
> 适用范围：MyNovel 长篇小说工作流

## 1. 背景

MyNovel 当前已经具备第一阶段金手指框架：

- 在 `novel-config.md` 中维护金手指设计档案、运行闭环、资源池、限制、升级树和信息流边界。
- 在分阶段细纲中维护实体物资账、系统资源账和逐章金手指交互。
- 在黄金三章中安排首次发现、首次操作、首次交易或验证。
- 在正文生成、审查和修复中检查规则漂移、能力越界、闭环缺失和升级验证。
- 在 `总结/主角状态仓库.md` 中维护金手指当前余额、权限、库存、模块和已验证规则。

这套框架主要解决“不能算错”和“不能写崩”，但没有充分解决“怎样设计得好玩”。当用户只提供题材、核心卖点和偏好时，AI 仍倾向于生成通用的任务、货币、模块升级树，把真正的玩法设计、经济设计和长期成长设计留给用户补全。

本次改造要在现有执行与记账框架之前增加独立的 AI 策划层，使 AI 能主动生成方案、比较方案、压力测试方案并规划阶段演化，用户主要负责纠正方向和口味。

## 2. 问题定义

### 2.1 当前能力

当前工作流能够回答：

- 金手指现在有什么。
- 本章获得和消耗了什么。
- 余额、库存、权限和模块能否从前文推导。
- 升级后是否安排了验证场景。
- 正文是否擅自新增了档案外功能。

### 2.2 当前缺口

当前工作流不能稳定回答：

- 为什么这个金手指值得读者持续期待。
- 主角反复执行哪些有趣的玩法动作。
- 一笔资源有哪些相互竞争的用途。
- 如何同时安排平滑成长和阶段跃升。
- 商店如何展示、锁定、刷新、涨价、限购或售罄。
- 如何避免货币通胀、奖励贬值和万能商店。
- 未来 50 章中需求、选择、投入、验证、回报和新短板如何循环。
- 同为经营文时，超市经营、载具养成、基地建设和空间种田为何需要不同状态模型。

### 2.3 根因

现有“金手指设计档案”是一份规则表，不是一套设计流程。现有大纲提示词要求 AI 填字段，却没有要求 AI：

1. 提出多个完整候选方案。
2. 解释候选方案与本书类型承诺的匹配关系。
3. 模拟长期玩法是否枯燥。
4. 对经济、选择密度和成长节奏进行压力测试。
5. 推荐方案并根据用户反馈重构。

## 3. 目标与非目标

### 3.1 目标

1. 用户只提供小说定位、核心卖点和少量偏好时，AI 能主动完成金手指初步设计。
2. AI 至少生成两套具有实质差异的完整方案，并推荐最适合的一套。
3. 每套方案同时包含玩法、经济、成长、限制、信息边界和剧情耦合，不以功能清单冒充设计。
4. 正式方案在进入总大纲前必须通过前 50 章可持续性模拟。
5. 每个 50 章规划段必须先生成金手指阶段规划，再生成逐章剧情细纲。
6. 复用现有“多维类型标签 + 类型承诺承载层”架构，不按都市、末世、玄幻等题材复制金手指模板。
7. 保持现有项目兼容；简单金手指不被迫增加复杂账本。

### 3.2 非目标

- 不让 AI 代替作者决定最终审美方向。
- 不追求模拟完整电子游戏经济系统。
- 不要求所有小说都拥有货币、商店、属性点或系统面板。
- 不把经营等同于开店；资产、基地、领地、空间和组织都可以构成经营对象。
- 不为每种小说题材建立独立目录或独立提示词。
- 不在本次改造中自动重写现有小说的金手指数值。

## 4. 核心设计原则

### 4.1 AI 先设计，用户校方向

设计流程默认由 AI 提案，而不是逐项要求用户填写。用户可以只回答高层偏好，例如：

- 更偏经营，不要纯任务升级。
- 小升级要频繁，大模块要稀缺。
- 不希望货币主要来自击杀。
- 系统感弱一些，小说感强一些。

AI 根据反馈重构完整方案，不把属性表、价格曲线和阶段演化重新交还用户填写。

### 4.2 小说类型与金手指机制正交

保留现有小说类型标签：

```text
主类型 + 爽点模式 + 叙事侧重 + 当前阶段功能
```

新增金手指机制画像：

```text
主机制画像 + 次机制画像 + 资源机制 + 反馈机制
```

小说类型决定读者期待看到什么，金手指机制决定主角怎样操作和成长。二者组合使用，不互相替代。

### 4.3 设计、计划、事实分层

```text
设计态：永久规则和允许空间
计划态：未来 50 章准备怎样发展
运行态：正文已经实际发生的当前状态
章节契约：本章怎样执行一次局部变化
```

计划不能提前写入运行态，运行态也不能反向覆盖永久规则。

### 4.4 选择比奖励更重要

金手指不能只提供“完成任务后自动变强”。资源应至少在以下用途之间形成竞争：

- 解决当前短板。
- 提升长期效率。
- 修复或维持既有资产。
- 保留应急储备。
- 为战略跃升继续积攒。

如果某次奖励只有一个显然正确的用途，它是结算，不是经营选择。

### 4.5 升级必须形成可感知变化

每次成长至少改变一项：

- 主角能做的新动作。
- 原有动作的效率、成本或风险。
- 可处理的需求或敌人范围。
- NPC、市场、势力或环境对主角的反应。
- 下一轮选择空间。

只增加面板数字而不改变场景结果，不算有效成长。

## 5. 总体架构

### 5.1 四层产物

| 层级 | 权威文件 | 职责 |
|---|---|---|
| 设计态 | `novel-config.md` | 永久规则、机制画像、玩法闭环、经济边界、成长拓扑、信息边界 |
| 计划态 | `plan/金手指发展_第X-Y章.md` | 当前 50 章的预算、商店演化、成长选择、验证节点和阶段结算 |
| 运行态 | `总结/主角状态仓库.md` 或 `总结/金手指状态仓库.md` | 当前余额、属性、库存、商品状态、冷却、权限、模块和债务 |
| 章节契约 | `plan/大纲_第X-Y章.md` 的逐章字段 | 起始状态、需求、候选方案、选择、支付、结果、反馈和下一轮需求 |

### 5.2 工作流

```text
小说定位与类型承诺
        ↓
金手指设计：候选方案 → 比较 → 压力测试 → 用户校方向 → 定稿
        ↓
写入 novel-config.md 的正式设计档案
        ↓
生成总大纲中的全书演化边界
        ↓
生成 plan/金手指发展_第X-Y章.md
        ↓
生成同范围剧情细纲
        ↓
正文执行 → 章节总结 → 状态仓库同步
        ↓
审查设计偏离、计划偏离、账目冲突和玩法疲劳
```

## 6. 金手指设计模型

### 6.1 通用设计内核

所有金手指先回答以下九项：

1. **核心幻想**：读者持续期待看到的根本结果。
2. **核心动词**：主角反复执行的动作，如购买、加点、建造、培育、复制、推演。
3. **输入资源**：货币、材料、时间、经验、情绪、风险、任务成果等。
4. **输出价值**：能力、商品、情报、资产、身份、秩序、关系或剧情通行权。
5. **选择结构**：资源有哪些竞争用途，放弃什么才能得到什么。
6. **成长拓扑**：平滑成长、子系统强化和战略跃升如何组合。
7. **限制代价**：容量、冷却、损耗、失败、维护、暴露和机会成本。
8. **兑现反馈**：如何通过场景结果、长期复利和外界反应证明投资价值。
9. **长期演化**：前期、中期、后期的玩法动作如何变化，而不只是数值变大。

### 6.2 机制画像

第一版在同一参考文档中维护下列画像，不分别创建目录：

| 机制画像 | 额外设计重点 |
|---|---|
| 商业经营 | 商品、货源、库存、定价、客户、支付能力、复购、利润和市场反馈 |
| 资产经营 | 产能、性能、维护、能源、空间、战损、设施、人员和折旧 |
| 基地/领地经营 | 人口、岗位、住房、治安、税费、公共服务、产能和秩序 |
| 属性加点 | 属性目录、等级上限、递增成本、前置条件、边际收益和场景验证 |
| 模块升级 | 模块槽位、前置模块、兼容、安装、维护、战损和玩法改变 |
| 空间种田 | 面积、地块、周期、产量、能耗、加工链、仓储和销售 |
| 签到抽奖 | 奖池、保底、冷却、重复奖励、领取条件和废奖处理 |
| 吞噬复制 | 槽位、来源、兼容、损耗、反噬、替换和组合规则 |
| 情报预知 | 范围、准确率、时效、盲区、验证成本和误判后果 |
| 传承技能 | 知识层级、熟练度、练习、使用代价、外显边界和社会验证 |

一本书允许组合多个画像，但必须指定一个主画像。主画像决定主要状态模型和高频玩法，次画像只能辅助，避免系统功能无限膨胀。

### 6.3 成长拓扑

经营和养成类金手指默认检查三级成长：

| 层级 | 频率 | 作用 |
|---|---|---|
| 平滑成长 | 高频 | 小幅改善具体短板，持续提供选择和反馈 |
| 子系统强化 | 中频 | 改变局部效率、操作方式或经营链条 |
| 战略跃升 | 低频 | 解锁新玩法、地图、客户群、生产链或冲突级别 |

不强制所有小说同时使用三级，但必须说明缺少某一级的原因和替代爽点。

### 6.4 经济健康检查

只要存在可累计资源或货币，设计时必须检查：

- 收入来源是否能被剧情稳定触发。
- 支出出口是否足以回收货币。
- 是否存在应急储备和未来大额目标。
- 价格增长是否与收入增长匹配。
- 旧商品是否仍有用途，还是解锁后立即报废。
- 是否存在唯一最优解导致虚假选择。
- 是否能通过维护、损耗、机会成本控制通胀，而不是随意涨价。
- 奖励是否会绕过现实物资、时间和社会规则。

### 6.5 任务引擎设计

任务不是临时发放奖励的借口，而是金手指连接“世界变化、主角行动和成长资源”的驱动器。只要金手指会主动派发任务，设计档案必须增加任务引擎；没有任务机制的金手指写“无任务引擎”，不得为了凑闭环强行添加。

#### 任务引擎的职责

- 把金手指能够感知的世界变化转化为可执行目标。
- 给主角提供方向、机会或压力，但保留判断、接受、拒绝和选择解法的空间。
- 将任务难度、风险和奖励接入金手指经济，形成可解释的资源来源。
- 通过成功、失败、放弃和部分完成产生剧情后果，而不是只有成功结算。
- 为阶段成长服务，但不得替代主角自身目标和人物动机。

#### 任务生成链

每个任务必须能够追溯以下因果链：

```text
系统感知来源
→ 可验证的触发条件
→ 为什么此刻生成任务
→ 为什么由主角执行
→ 目标与完成判定
→ 奖励、失败和放弃后果
```

系统只能根据设计档案允许的传感器、绑定对象、规则判定或已接收信息生成任务。系统不知道的信息不能用来发布精准任务；如任务本身包含未知情报，必须解释情报来源、可信度和信息费用。

#### 任务类型

| 任务类型 | 主要功能 | 使用限制 |
|---|---|---|
| 新手引导 | 教会首次操作和基本闭环 | 数量有限，完成后退出，不能长期替主角做决定 |
| 生存/维护 | 应对环境、能源、战损、设施或人员压力 | 必须来自真实状态，不得凭空制造倒计时 |
| 机会任务 | 提供稀缺资源、图纸、客户、地点或情报窗口 | 允许拒绝或错过，奖励对应机会成本 |
| 里程碑任务 | 推动阶段升级、权限解锁或战略跃升 | 需要前置积累，不能临危突然完成 |
| 探索任务 | 引导新地图、未知规则或资源点 | 情报必须受系统感知边界限制 |
| 对抗任务 | 处理已经形成敌意或威胁的目标 | 不得把普通冲突随意判定为可刷分敌人 |
| 经营任务 | 营业额、交付、生产、客户、秩序或服务目标 | 指标必须能被主角经营行为影响，不能只靠剧情送客 |
| 可选挑战 | 用更高风险换额外奖励 | 必须明确基础完成条件和额外条件，不能结算时临时加码 |

同一小说不必使用全部类型。设计时选择 3 至 5 个主任务类型，并说明其他类型为何不用，避免任务系统无所不能。

#### 单个任务契约

```markdown
| 字段 | 内容 |
|---|---|
| 任务ID/名称 | 稳定标识和可读名称 |
| 类型/层级 | 引导、维护、机会、里程碑等；普通/困难/阶段级 |
| 感知来源 | 系统通过什么已知信息发现需求或威胁 |
| 触发条件 | 哪些事实成立后才生成，不得追溯补发 |
| 派发理由 | 为什么任务符合金手指目标和当前阶段 |
| 接受规则 | 自动进入、可接受、可拒绝、可延后或互斥 |
| 任务目标 | 主角实际需要完成什么 |
| 完成判定 | 可观察、可验证、不可任意解释的成功条件 |
| 可用解法 | 单一路径或多路径；是否允许超额完成 |
| 时限 | 来源和合理性；无真实时间压力时不强加倒计时 |
| 基础奖励 | 与难度、成本、风险和阶段经济匹配的奖励 |
| 可选奖励 | 额外目标对应的额外收益 |
| 失败/放弃后果 | 世界自然后果、机会丧失或已约定惩罚 |
| 反作弊边界 | 防重复刷取、目标判定、同类任务冷却和恶意利用 |
| 剧情后果 | 成功或失败后怎样改变环境、关系、敌情或下一轮需求 |
```

#### 任务合理性闸门

派发任务前必须全部检查：

1. **信息合理**：系统确实能感知触发事实，不使用作者全知视角。
2. **时机合理**：任务由当前状态或事件触发，不在危机发生后追溯补发奖励。
3. **动机合理**：任务符合金手指的核心目标，不随剧情需要任意改变价值观。
4. **能力合理**：派发时主角具备完成的理论路径；高风险不等于必死或只能靠临时外挂。
5. **时间合理**：时限来自天气、距离、库存、敌人行动或交易窗口，而不是为了刺激强加倒计时。
6. **奖励合理**：奖励与难度、风险、投入和当前经济规模匹配，不因作者急需升级而暴涨。
7. **惩罚合理**：可选任务原则上以失去机会和世界自然后果为主；强制惩罚必须由预先确认的系统规则支持。
8. **判定合理**：成功条件在派发时明确，结算时不得临时改变口径。
9. **主角能动性**：主角仍需要判断、准备和选择解法，不能只按系统箭头行动。
10. **剧情合理**：任务解决现实存在的问题，并在结算后留下可见结果，不形成封闭的系统自嗨。

#### 任务经济规则

- 先设计阶段可承受的总奖励区间，再分配到具体任务，避免逐章临时定价。
- 奖励来源必须与系统目标相关：生存系统奖励有效存活与资产改善，经营系统奖励真实交易与履约，不能什么行为都兑换同一种货币。
- 日常可重复任务使用递减收益、冷却、次数上限或状态门槛，防止无限刷取。
- 高额奖励优先绑定阶段里程碑、重大风险或长期投入，不绑定偶然出现的弱小敌人。
- 任务奖励提供选择，不默认自动购买指定升级；任务与商店之间保留决策环节。
- 实物、权限、图纸和货币奖励分别记账，不用模糊的“丰厚奖励”跳过经济核算。

#### 任务与主线的关系

主角可以由任务启动行动，但不能长期只有系统动机。任务规划应区分：

- **主角本来就要做，系统确认价值并提供奖励**：强化人物目标，优先使用。
- **系统提供主角原本不知道的机会**：必须支付信息成本或服从感知边界。
- **系统要求主角改变计划**：必须形成是否接受的真实取舍。
- **主角主动创造条件触发任务**：允许策略经营，但受反作弊和重复触发规则限制。

任务驱动的理想状态是“系统提供方向和反馈，主角决定是否做、怎样做以及承担什么”，而不是“系统发布命令，主角机械执行”。

## 7. AI 设计流程

### 7.1 输入

优先读取：

- 小说类型标签与类型承诺。
- 核心卖点、主角目标和世界压力。
- 用户已经明确的金手指偏好与禁区。
- 对标作品中已通过原创性闸门的抽象机制。
- 既有项目的设计档案、总大纲和当前状态。

信息不足时，AI 每次只询问一个会实质改变方案方向的问题。可由 AI 合理设计的字段不得反问用户逐项填写。

### 7.2 候选方案

默认生成 2 至 3 套完整候选。候选必须在核心动词、资源来源、成长方式或限制机制上有实质差异，不能只是商品名称不同。

每套候选至少输出：

- 一句话核心幻想。
- 主画像与次画像。
- 高频玩法循环。
- 经济和成长模型。
- 前 20 章的典型体验。
- 中后期扩展空间。
- 主要风险和修正办法。
- 与本书类型承诺的匹配度。

### 7.3 压力测试

AI 在推荐前内部模拟以下问题，并把关键结论展示给用户：

- 前 10 章能否完成发现、第一次操作、第一次选择和第一次兑现。
- 前 50 章是否至少产生三种不同的资源取舍。
- 连续 10 章是否可能只剩任务提示和自动升级。
- 主角是否会因金手指过强而失去现实需求、冲突或行动必要性。
- 经济是否在中期迅速通胀或陷入长期攒点。
- 每次升级是否只是数值变大，没有新场景动作。
- 外界反馈是否只有震惊，缺少交易、模仿、觊觎、依赖、误判或秩序变化。
- 后期扩展是否需要违反前期硬规则。

### 7.4 推荐与校准

AI 推荐一套主方案，同时指出可以吸收的其他方案组件。用户给出方向反馈后，AI 必须重构整套相关链路，不能只局部增加一个功能导致经济和限制失衡。

### 7.5 定稿

用户确认方向后，生成正式设计档案并写回 `novel-config.md`。未确认的候选方案不得进入正式配置、状态仓库或正文上下文。

## 8. 金手指阶段规划

### 8.1 生成时机

- 总大纲确认后、黄金三章和第 1-50 章常规细纲前，生成 `plan/金手指发展_第1-50章.md`。
- 后续每个 50 章窗口，在生成同范围剧情细纲前生成对应金手指发展文件。
- 无金手指小说不创建空文件。
- 金手指不发生阶段变化且结构简单时，可在细纲前置分析中写“沿用设计档案，无独立阶段文件”，但必须说明理由。

### 8.2 文件内容

```markdown
# 金手指发展_第X-Y章

## 期初状态与阶段目标
- 期初运行状态：
- 期末目标状态：
- 本阶段主成长轴：
- 本阶段次成长轴：
- 本阶段禁止提前解锁：

## 资源预算
| 资源 | 期初 | 预计收入区间 | 必要支出 | 可选投资 | 应急储备 | 期末目标区间 |

## 商店与可选项快照
| 项目 | 当前状态 | 当前价格 | 前置条件 | 本阶段计划变化 | 计划决策章 | 验证章 |

## 阶段任务池（如有任务引擎）
| 任务/类型 | 感知来源与触发条件 | 接受规则 | 目标与判定 | 奖励预算 | 失败/放弃后果 | 计划触发章 | 计划结算章 | 后续影响 |

## 五章玩法循环
| 章节组 | 产生需求/任务触发 | 候选方案 | 选择与机会成本 | 执行/场景验证 | 结算与长期回报/新短板 | 外界反馈 |

## 战略跃升
| 节点 | 解锁条件 | 改变的玩法 | 代价 | 验证场景 | 后续压力 |

## 阶段末结算
- 已兑现的核心幻想：
- 仍保留的选择：
- 下一阶段期待：
```

预算使用区间而非强制精确预测，避免剧情轻微变化造成整段计划失效。已发生的准确数值仍由运行态仓库维护。

### 8.3 五章玩法循环

每个五章组检查是否形成：

```text
产生需求 → 展示选择 → 资源取舍 → 操作或购买
→ 场景验证 → 长期收益或新短板 → 下一轮期待
```

不是每五章都必须购买或升级。可以用维护、攒点、错过限时项、放弃某条路线、旧投资复利等方式完成经营体验。

## 9. 运行态仓库

### 9.1 拆分条件

默认继续在 `总结/主角状态仓库.md` 内维护“金手指动态状态”。同时满足以下任意两项时，拆出 `总结/金手指状态仓库.md`：

- 两种及以上可累计系统资源或货币。
- 存在商店目录、锁定、刷新、限购或库存。
- 存在三条及以上成长分支。

## 13. 现有小说兼容与迁移

### 13.1 不自动迁移

已有小说不会因为 Skill 更新而自动生成新文件或修改设定。继续写作前进行一次轻量诊断：

- 现有设计是否足以支持后续阶段。
- 是否存在长期只有唯一升级选项的问题。
- 是否需要独立状态仓库。
- 是否需要从当前章开始补阶段规划。

### 13.2 迁移策略

- **简单且稳定**：保留现状，仅补缺失的阶段规划摘要。
- **复杂但账目清楚**：从当前有效章节建立独立金手指仓库，不追溯重写全部历史。
- **设计不足**：进入“金手指重构”路由；先保护正文已验证规则，再设计未来可扩展部分。
- **正文与设计冲突**：正文证据优先，修订设计档案并记录规则为何变化；不得默默抹除已发生事实。

## 14. 《陆地航母》应用示例

### 14.1 机制画像

```text
主画像：资产经营
次画像：属性加点 + 模块升级
资源机制：任务货币 + 系统商店
反馈机制：生存效率 + 战车性能 + 外界反差
```

### 14.2 三级成长

- 平滑成长：轮胎抓地、防爆、油耗、扭矩、装甲、储物利用率、低温启动。
- 子系统强化：态势监控并发、燃油过滤、维修效率、水循环、生活区能耗。
- 战略模块：破冰履带、高压电网、温室舱、武器模块、能源核心。

### 14.3 典型选择

```text
当前余额 400 生存点

方案 A：强化轮胎抓地，立即降低冰面失控风险
方案 B：提升燃油效率，为南下保存长期续航
方案 C：修复装甲，恢复当前安全余量
方案 D：保留 400 点，继续积攒破冰履带前置费用
```

细纲必须结合当前道路、燃油、敌情和阶段目标说明选择理由，并在后续场景验证。系统不替主角自动选择。

### 14.4 任务引擎示例

《陆地航母》的任务系统应以绑定载具的环境监测、战损状态、导航数据和明确敌意行为为感知来源，不允许无条件扫描全城或知道封闭建筑中的秘密。

```markdown
| 字段 | 示例 |
|---|---|
| 任务 | 初级极寒生存 |
| 类型 | 生存/维护任务 |
| 感知来源 | 车载温度、气象数据、供电和燃油状态 |
| 触发条件 | 外界温度进入初级极寒阈值，绑定载具仍在运行 |
| 目标 | 在规定低温周期内维持载具核心系统运行并保证绑定者存活 |
| 完成判定 | 温度周期结束；核心系统未永久停机；主角存活 |
| 可用解法 | 补充燃油、降低能耗、维修、寻找避风点或升级保温 |
| 奖励 | 阶段预算内的生存点 + 生活区权限，不自动附送完整生活设施 |
| 失败后果 | 任务不结算；载具和人物承受现实低温与停机后果 |
| 反作弊 | 同一轮气象事件只结算一次；不能反复进出低温区刷取 |
| 后续影响 | 权限解锁后仍需现实材料和点数建设生活区 |
```

“遭遇敌人就奖励击杀点”不应成为唯一收入来源。阶段任务池应混合环境生存、资产维护、路线探索、资源运输、阶段里程碑和明确敌意对抗，使任务服务于重卡经营，而不是把小说写成重复刷怪。

## 15. 审查新增问题类型

### 15.1 设计层问题

- 核心动词单一，连续多轮只有领取任务和自动升级。
- 主画像不清，多个辅助系统无边界叠加。
- 收入、支出或价格曲线无法长期成立。
- 前期规则无法支撑后期扩展，只能靠临时新增万能功能。
- 任务系统没有感知边界、派发目标或稳定价值观，任务只服从作者临时需要。
- 所有成长资源都来自击杀或打脸任务，导致剧情和经济只能靠重复制造敌人。

### 15.2 计划层问题

- 连续多个五章组没有实际选择、验证或长期回报。
- 阶段规划只有解锁清单，没有需求和机会成本。
- 计划收入与剧情触发条件不匹配。
- 战略模块提前解锁或没有铺垫。
- 阶段任务没有总奖励预算，后期奖励随剧情需要任意膨胀。
- 任务触发、接受、执行和结算挤在同一场景，没有准备、取舍或后果。

### 15.3 正文层问题

- 虚假选择：表面列出多个选项，实际上只有一个合理答案。
- 免费补丁：系统在危机时临时赠送正好解决问题的功能。
- 面板代替场景：只写数字变化，没有行动和结果。
- 反馈单一：每次都只有 NPC 震惊，没有市场、关系、敌情或秩序变化。
- 旧投资失效：升级后旧商品、旧模块和旧经营成果立即失去价值。
- 全知任务：系统无感知来源地准确指出远处敌人、隐藏物资或幕后真相。
- 救场任务：危机发生后临时派发恰好提供解法或足额奖励的任务。
- 追溯任务：主角先完成行为，系统事后补发未提前定义的任务奖励。
- 判定漂移：派发时目标模糊，结算时按剧情需要改变完成标准。
- 奖惩失衡：简单行为获得巨额奖励，或可选任务失败遭受未预告的强制惩罚。
- 木偶驱动：主角没有自己的目标和判断，只按系统指令逐项行动。

设计或经济结构问题不得由正文自动修复。标记为 structural，退回金手指阶段规划或设计档案处理。

## 16. 测试与验收

### 16.1 文档契约测试

在 `tests/test_skill_docs.py` 中至少验证：

- `SKILL.md` 存在两条新路由并引用新文件。
- 设计提示词要求候选方案、压力测试、推荐、用户校准和正式定稿。
- 有任务机制时，设计提示词要求任务生成链、任务类型、单任务契约、合理性闸门和任务经济。
- 阶段规划提示词要求预算、商店快照、五章玩法循环和战略跃升。
- 阶段规划提示词要求任务池、阶段总奖励预算、触发章和结算章。
- 分阶段细纲读取对应范围的金手指发展文件。
- 上下文组装能在主角仓库和独立仓库之间正确分流。
- 正文审查识别虚假选择、免费补丁、玩法重复和面板代替场景。
- 正文审查识别全知任务、救场任务、追溯奖励、判定漂移、奖惩失衡和木偶驱动。
- 无金手指和简单金手指不会被强制创建空文件或复杂仓库。

### 16.2 前向测试样本

使用三个互不泄露预期答案的真实任务测试：

1. **资产经营**：《陆地航母》，检查 AI 是否主动设计属性加点、维护、模块和资源取舍。
2. **商业经营**：《末世万界小超市》，检查库存、顾客支付能力、复购、定价和外部经济。
3. **非经营型能力**：《大医无双》或全新传承能力样本，检查是否避免强行添加商店和货币。

每个样本评估：

- 是否形成不同而完整的候选方案。
- 是否能解释推荐依据。
- 是否能支持前 50 章而不快速枯竭。
- 是否产生真实选择而非唯一最优解。
- 是否遵守类型承诺和能力表现边界。
- 是否正确选择内嵌或独立状态仓库。
- 任务是否有合理感知来源、触发条件、完成判定、奖励预算和失败后果。

### 16.3 验收标准

本次改造完成后，给定“末世重卡、偏经营、最终成为陆地航母”这一层级的输入，AI 应当能够：

1. 主动提出至少两套机制不同的完整金手指方案。
2. 推荐资产经营 + 属性加点 + 模块升级组合，并说明取舍。
3. 生成基本经济、属性和商店框架，而不是要求用户逐项填写。
4. 模拟前 50 章的需求、选择、投入、验证和回报节奏。
5. 在用户只说“经营感不够”后，主动重构方案并保持账目与限制一致。
6. 将确认后的设计、阶段计划和当前事实写入各自权威文件。
7. 设计环境、维护、探索、里程碑和对抗等任务来源，避免只能靠重复击杀赚取生存点。
8. 对每个阶段任务说明系统为何知道、为何此时派发、为何奖励这些内容以及失败会自然造成什么。

## 17. 实施顺序

### 阶段一：锁定新契约

1. 在测试中加入新路由、新文件和分层权威的失败断言。
2. 保留现有金手指闭环、状态仓库和类型承诺测试。

### 阶段二：建立设计能力

1. 新增 `references/金手指设计与运营.md`。
2. 新增 `prompts/金手指设计提示词.md`。
3. 在 `SKILL.md` 和大纲生成流程中接入设计/重构路由。

### 阶段三：建立阶段规划能力

1. 新增 `prompts/金手指阶段规划提示词.md`。
2. 登记 `plan/金手指发展_第X-Y章.md`。
3. 修改黄金三章和分阶段细纲的前置输入与章节契约。

### 阶段四：接入执行、总结和审查

1. 更新上下文组装与状态仓库拆分规则。
2. 更新草稿生成、审查、修复和总结流程。
3. 增加 structural 回退规则。

### 阶段五：验证

1. 运行文档契约测试和完整测试。
2. 复读所有修改文件，检查术语和权威源一致。
3. 用三类小说进行隔离前向测试。
4. 根据失败样本迭代参考文档和提示词。

## 18. 最终决策摘要

- 保留现有类型承诺系统，不另建按题材划分的金手指目录。
- 新增金手指机制画像，与小说类型标签正交组合。
- 对派发任务型金手指增加任务引擎，维护感知、触发、接受、判定、奖惩、反作弊和剧情后果。
- 保留现有设计档案和状态仓库，将其定位为规则与执行层。
- 新增 AI 主导的金手指设计流程，用户负责方向校准。
- 新增每 50 章一份金手指发展计划，先规划玩法再生成剧情细纲。
- 简单金手指继续内嵌主角状态仓库，复杂金手指按明确条件拆分。
- 第一版只新增一个参考文档和两个提示词，不拆出大量类型文件。
- 设计、经济或成长结构问题退回设计/阶段规划层，正文不得擅自补系统功能。
