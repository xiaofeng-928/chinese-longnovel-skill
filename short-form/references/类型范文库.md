# 类型范文库维护

范文参照库位于 `D:\ai小说\短篇\<作品类型>\范文参照`，服务于该作品类型下所有具体作品。

| 文件或目录 | 用途 |
|---|---|
| `范文合集.txt` | 已确认可供参考的范文集合 |
| `范文\` | 每篇范文一个 Markdown 文件；保存元数据快照、合法导入的正文和精读笔记 |
| `类型创作特征.md` | 从范文与扫榜结果提炼出的可执行类型特征 |
| `扫榜记录\` | 带来源与日期的榜单、样本和观察记录 |

更新范文前，区分原始观察、提炼结论和可直接参考的范文内容；不要把未经核实的信息写入“类型创作特征”。每篇 `范文/NNN_作品名.md` 至少保留：标题、平台、合集、抓取日期、来源链接、来源状态和元数据快照。链接失效时，以本地快照继续识别作品，不将失效链接视为正文证据。参考范文时，只吸收结构、节奏、冲突与题材模式，不复用具体人物、情节、段落或表达。具体作品使用范文参照库后，将实际参考项写入该作品的 `参考素材.txt`。

正文写入规则：只有用户手动提供、明确授权使用，或确认具有合法使用权的文本，才写入单篇 Markdown 的“正文”区。未取得正文时保留“待导入”标记，严禁将标题、简介或模型推测伪装成原文。

## 快速扫榜

1. 优先处理用户提供或可核实的目标平台公开榜单、公开目录或 API，并在首次成功响应后保存相关元数据快照。
2. 先从榜单选合集，再从合集目录筛作品；同一平台请求并发最多 3 个，单个请求最多重试 2 次。
3. 搜索引擎只能用于定位官方入口；不得用搜索摘要充当作品证据，也不得反复更换搜索引擎凑样本。
4. 官方榜单、目录或正文证据缺失时，停止该样本并在扫榜报告标记“待补证”，不得猜测标题、剧情、标签、开篇或结局。
5. 每次至少收集 5 个同平台样本；样本不足时明确标记“样本不足”。扫榜结束时写入来源链接、榜位、日期、字数和互动数据，避免链接变更后失去已核验事实。

## 扫榜脚本

`scripts/扫榜.py` 接收用户提供或外部工具取得的 JSON 样本，统计高频标签、开篇钩子、人物关系、核心冲突和结局模式。每次运行写入 `扫榜记录/<日期>_扫榜.md`，并保留平台、来源 URL 与日期。

```powershell
py -3 C:\Users\Lenovo\.claude\skills\MyNovel\short-form\scripts\扫榜.py --input D:\数据\老福特.json --type-dir D:\ai小说\短篇\老福特 --update-features --format markdown
```

默认不改写 `范文合集.txt`；只有用户确认样本适合作为范文时才加入。`--update-features` 只更新 `类型创作特征.md` 中带自动标记的区块，保留人工维护的内容。
